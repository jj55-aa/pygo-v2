# 统计与汇总——数据工坊第二步

## 🧮 统计三件套：求和、计数、平均

数据工坊的传送带上送来一摞工资数据：8000、9000、8500……工头要的不再是「一条一条看」，而是三个数字：**一共发了多少钱（求和）、一共有多少人（计数）、平均每人多少钱（平均）**。这就好比工坊里的「称重计数台」：称总重、数件数、再算单件平均重。

Python 里这三件事各有一个内置函数，合称**统计三件套**：

- **求和 SUM**：`sum(数据)`——把列表里所有数字加起来
- **计数 COUNT**：`len(数据)`——数一数列表里有多少个元素
- **平均值 AVG**：`sum(数据) / len(数据)`——总和除以个数

```python
salaries = [8000, 9000, 8500]

print("工资总和：", sum(salaries))                 # 求和 SUM → 25500
print("员工人数：", len(salaries))                 # 计数 COUNT → 3
print("平均工资：", sum(salaries) / len(salaries)) # 平均 AVG → 8500.0
```

> ⚠️ 新手最容易踩的坑：
> 1. **先转数字再统计**：`input()` 拿到的一律是字符串，`"8000" + "9000"` 是拼接成 `"80009000"`，不是加法。要先用 `int()` / `float()` 转成数字再算。
> 2. 平均 = **总和 ÷ 个数**，只算 `sum()` 得到的是总和不是平均；除出来的结果是浮点数（如 8500.0）。
> 3. 求和直接用内置 `sum()`，别自己写循环从 0 加起——能用现成工具就别重复造轮子。

## 🗂️ 分组统计：字典就是「分组账本」

报表里的数据是混在一起的一长串：技术部 8000、市场部 9000、技术部 8500……要按部门统计，就得先**分组**。想象数据工坊的「分装流水线」：传送带旁摆着一排贴了标签的箱子，来一条数据就往对应标签的箱子里扔一份——技术部的进技术部箱子，市场部的进市场部箱子。每个箱子越堆越高，最后看看每个箱子有多少。

Python 里这排「贴标签的箱子」就是**字典**：**键是分组名（部门），值是累加的结果**。字典当分组账本，三步走：

1. 拆开一行数据：`dept, wage = line.split(",")`
2. 键不存在时从 0 开始：`total.get(dept, 0)`
3. 累加回去：`total[dept] = total.get(dept, 0) + wage`

```python
# 每一行格式：部门,工资
rows = ["技术部,8000", "技术部,8500", "市场部,9000", "行政部,6000"]
total = {}                          # 空账本：部门 → 工资合计
for row in rows:
    dept, wage = row.split(",")     # 拆成部门名和工资
    dept = dept.strip()             # 分组键先清理首尾空格
    wage = int(wage)                # 工资转成数字
    total[dept] = total.get(dept, 0) + wage   # 关键一行：累加

print(total)   # {'技术部': 16500, '市场部': 9000, '行政部': 6000}
```

`total.get(dept, 0)` 是分组账本的「保险丝」：键存在就返回当前合计，键不存在就返回 0——第一次遇到新部门，从 0 开始加。

> ⚠️ 新手最容易踩的坑：
> 1. **分组键先 `strip()`**：`"技术部 "` 和 `"技术部"` 是字典里**两个不同的键**，不清理空格，同一个部门会被统计成两堆！
> 2. 键不存在时**不能直接 `total[dept] += wage`**：会报 `KeyError`。记住初始化写法 `total.get(dept, 0)`。
> 3. 工资要 `int()` 转数字再累加：字符串 `+` 是拼接，`"8000" + "9000"` 会变成 `"80009000"`。

## 🏆 极值与排序：挑最大、最小，排个序

工头盯着账本问：「哪个部门工资最高？哪个最低？按合计排个序我看看。」——这就是**极值与排序**。数据工坊里有一面「排行榜」墙：

- `max(数据)`：最大值（榜首）
- `min(数据)`：最小值（榜尾）
- `sorted(数据)`：从小到大排序（升序）
- `sorted(数据, reverse=True)`：从大到小排序（降序）

```python
salaries = [8000, 9000, 8500]
print(max(salaries))                      # 9000
print(min(salaries))                      # 8000
print(sorted(salaries))                   # [8000, 8500, 9000]
print(sorted(salaries, reverse=True))     # [9000, 8500, 8000]

# 分组账本排序：默认按「键」（部门名）排
total = {"技术部": 16500, "市场部": 9000, "行政部": 6000}
print(sorted(total))                      # 按部门名排
# 想按「值」（合计）排：sorted(账本.items(), key=lambda x: x[1])
print(sorted(total.items(), key=lambda x: x[1], reverse=True))
```

- 对字典 `sorted(d)` 排的是**键**（分组名）
- 想按**值**（统计结果）排，用 `sorted(d.items(), key=lambda x: x[1])`；加 `reverse=True` 变降序

> ⚠️ 新手最容易踩的坑：
> 1. `sorted()` **不改原列表**，返回一个排好序的新列表；想原地改列表才用 `.sort()`。
> 2. 字典直接 `sorted(d)` 排的是**键不是值**——要按统计结果排序，必须用 `key=lambda x: x[1]` 指明取第二项（值）。
> 3. `max` / `min` 比的是元素本身：数字比大小没问题；字符串比的是字典序，别拿字符串去和数字比大小。

## 🐼 pandas 的 groupby：一键分装

前面的「字典 + 循环」分组，像工坊里的**手工分装流水线**——慢，但每一步都看得懂。真实项目里处理 Excel 报表，用的是数据分析库 pandas 的 `groupby`——相当于一台**一键分装机械臂**：读入整张表，按某一列分组，一条命令直接出统计结果。

**概念**：`df.groupby("部门")["工资"].sum()` 读作「按『部门』分组，对『工资』列求和」——这正是我们用字典账本做的事：**先按分组键归堆，再对每堆做统计（求和/计数/平均）**。

```python
# 真实项目（本机装有 pandas 才能运行）：
import pandas as pd
df = pd.read_excel("工资表.xlsx")          # 读入 Excel 表格
print(df.groupby("部门")["工资"].sum())     # 按部门分组求和
print(df.groupby("部门")["工资"].mean())    # 按部门分组求平均
print(df.groupby("部门")["工资"].count())   # 按部门分组计数
```

> 注意：本课的在线练习环境（Pyodide）没有 pandas，所以练习统一用「列表 + 字典」模拟分组统计——但背后的思想一模一样。**原理通了，以后学 pandas 就是换工具而已。**

> ⚠️ 新手最容易踩的坑：
> 1. `groupby` 的列名要**和表头精确一致**（大小写、空格都不能差），否则报 `KeyError`——和字典取键一个道理。
> 2. `groupby` 是「分组 + 聚合」两步：先 `groupby("列名")` 分组，再 `.sum()` / `.mean()` / `.count()` 聚合，**少一步都出不了结果**。
> 3. 聚合前先把列转成数字类型（`.astype(int)`），Excel 里存成文本的数字，`sum` 会算出奇怪的结果。
