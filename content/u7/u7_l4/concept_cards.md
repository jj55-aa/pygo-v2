# 综合实战——档案馆的结业大考

## 🏭 数据处理四步套路：档案馆的「档案流水线」

老馆长处理堆积如山的卷宗，从来都是同一条流水线：**调卷 → 拆卷 → 统计 → 归档**。程序处理一批文件数据，走的也是同一条流水线，只四步：

**读 → 拆 → 算 → 写**

| 步骤 | 档案馆比喻 | 代码对应 |
| --- | --- | --- |
| 读 | 把整堆卷宗搬到桌上 | `sys.stdin.read()` / `for line in f` |
| 拆 | 把每份卷宗拆开看字段 | `line.split(",")` |
| 算 | 数人数、算总分、挑达标的 | 循环 + 计数器/累加器/条件 |
| 写 | 把结果归档进新卷宗 | `f.write()` / `print()` |

```python
import io

# 读：把「档案文件」整体读进来（io.StringIO 模拟文件）
data = io.StringIO("小明,90\n小红,85\n")

count = 0
total = 0
for line in data:                            # 读：逐行读取
    name, score = line.strip().split(",")    # 拆：按逗号拆出姓名和分数
    total += int(score)                      # 算：分数转数字并累加
    count += 1                               # 算：人数 +1

print("共", count, "人，总分", total)        # 写：把结果输出 / 存进新档案
```

> ⚠️ 易错点：四步别混着写。**「拆」出来的字段全是字符串**，要算数必须先 `int()` / `float()` 转数字；「写」之前想清楚是覆盖（w）、追加（a）还是新建文件——`print` 输出到屏幕、`f.write` 落进文件，两条路都算「写」。

## ✂️ 按行解析与 split：拆开每一份卷宗

档案馆里的每份卷宗都像一行「姓名,分数」的文本。要把里面的姓名和分数提取出来，用 **`split()` 按分隔符拆开**：

**split(分隔符)** = 把字符串按分隔符切成一个列表，一个字段一个元素。

```python
line = "小明,90"
parts = line.split(",")      # 按逗号拆 → ['小明', '90']
name = parts[0]              # 姓名：小明
score = int(parts[1])        # 分数：90（字符串要转数字才能算！）
```

配合 `for line in 文件` 就能逐行处理整个文件。前面先 `line.strip()` 去掉行尾的换行符和空白，拆出来的字段才干净。

> ⚠️ 易错点：读文件出来的每行末尾常带着换行符 `\n`（`"小明,90\n"`），虽然 `int()` 能容忍它，但字段里带着它做字符串比较（`name == "小明"`）会莫名失败——**先 `strip()` 再 `split()`**；另外 CSV 里拆出来的全是字符串，别拿字符串直接做加法（`"90" + "85"` 会变成 `"9085"`）。

## 📊 统计与筛选：数一数、加一加、挑一挑

处理档案最常用的三个动作：**计数**（多少人）、**求和**（总分）、**筛选**（只留达标的）。套路都是「循环 + 变量」：

```python
count = 0          # 计数：先归零
total = 0          # 求和：先归零
passed = []        # 筛选：及格的收集起来
for s in [90, 85, 62, 98]:
    count += 1
    total += s
    if s >= 60:            # 条件筛选
        passed.append(s)
print(count, total, passed)   # 4 335 [90, 85, 98]
```

> ⚠️ 易错点：计数/求和变量要**先初始化为 0，且放在循环外面**——放里面会被每轮循环重置，数出来永远是 1；筛选的 if 条件写反（`>=` 写成 `<=`）是最高频的隐性 bug：程序不报错，但结果全错，还特别难查。

## 🛡️ 异常兜底：FileNotFoundError 的友好提示

打开文件最常见的意外是**文件不存在**：`open("没有的档案.txt", "r")` 直接抛 **FileNotFoundError**，程序当场崩给用户看。u6 学的防御式编程正好派上用场——用 try/except 接住它，给一句人话提示：

**FileNotFoundError** = 用只读模式打开不存在的文件时抛出的异常。它和 `ValueError`、`ZeroDivisionError` 一样，是 Python 内置的异常类型。

```python
try:
    with open("records.txt", "r", encoding="utf-8") as f:
        print(f.read())
except FileNotFoundError:
    print("档案没找到，请检查文件名和路径")
```

> ⚠️ 易错点：**只有只读模式（"r"）才会抛 FileNotFoundError**——用 "w" 打开不存在的文件不会报错，它会**自动新建**（但也可能清空你要保留的旧文件）。except 要写**具体异常类型** `except FileNotFoundError`，别写裸 `except:` 把别的 bug 也悄悄吞掉。
