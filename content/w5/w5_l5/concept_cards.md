# 独立挑战——守卫塔的结业大考

## 🛡️ 审计四要素：守卫塔的「四关」

**类比**：守卫塔是项目上线前的最后一道大门，塔主把关有四关：**功能关**（项目能不能用）、**安全关**（代码安不安全、会不会被攻破）、**数据关**（用户数据丢不丢、坏了能不能恢复）、**运维关**（上线之后活不活、出问题能不能及时发现）。四关全过，塔主才放行；任何一关没过，项目就只能留在塔外。

**定义**：**上线前审计四要素** = 功能（功能/测试/跑通）+ 安全（安全/审计/密钥/防火墙）+ 数据（数据/备份/恢复）+ 运维（运维/日志/监控）。上线前审计，就是把这四关一关一关过一遍：功能有没有测过、安全有没有防护、数据有没有备份、运维有没有监控——四关齐全，项目才敢上线。

```python
# 用字典模拟「审计四要素」清单：每一关 + 它的关键词
audit = {
    "功能": ["功能", "测试", "跑通"],
    "安全": ["安全", "审计", "密钥", "防火墙"],
    "数据": ["数据", "备份", "恢复"],
    "运维": ["运维", "日志", "监控"],
}
for gate, words in audit.items():
    print(gate, "关关键词：", words)
```

> ⚠️ 易错点：
> 1. **四关缺一不可**：功能跑通了就以为能上线？密码明文、没有备份、日志不看的项目，上线就是事故现场。四关是「并且」的关系，不是「随便过几关就行」。
> 2. **别把其他课的四件套混进来**：服务器/域名/环境/启动是 w4 部署方案四件套，前端/后端/数据库/工具是 w3 项目骨架——审计四要素是 功能/安全/数据/运维，管的不是「怎么上线」，而是「上线前检查什么」。

## 🔍 评估方法：按关键词给四关打分

**类比**：塔主检查情况说明，像体检一样**按关键词扫描**：每一关都有几个「信号词」，说明里出现哪个词，就说明它提到了哪一关——功能关看 功能/测试/跑通，安全关看 安全/审计/密钥/防火墙，数据关看 数据/备份/恢复，运维关看 运维/日志/监控。

**定义**：**评估方法** = 用四组关键词扫描「上线前情况说明」文本，数一数**每类命中几个关键词**（同一个词出现多次只算一次）。计分规则：每类最多算 **2 分**（命中 2 个及以上都算满），四类满分 **8 分**——分数越高，项目越接近「可以上线」。

```python
text = "功能测试全部跑通，每天备份数据库，日志实时监控"
keys = {
    "功能": ["功能", "测试", "跑通"],
    "安全": ["安全", "审计", "密钥", "防火墙"],
    "数据": ["数据", "备份", "恢复"],
    "运维": ["运维", "日志", "监控"],
}
total = 0
for name, words in keys.items():
    hit = sum(1 for w in words if w in text)   # 命中几个关键词（去重）
    total += min(hit, 2)                        # 每类最多 2 分
    print(name, "命中", hit, "个关键词")
print("上线就绪度：", total, "分（满分 8）")
```

> ⚠️ 易错点：
> 1. **命中要「去重」**：一个关键词出现三次（比如「测试、测试、再测试」）也只算命中一次；计分封顶每类 2 分，不是关键词出现越多分越高。
> 2. **匹配是「包含」不是「相等」**：`"数据" in text` 是子串匹配——「数据库」里也包含「数据」，会算命中；这不叫 bug，是关键词扫描的正常行为，想清楚再用。

## 🔧 缺失分析：哪一关最该补强

**类比**：体检报告出来，哪项指标最低就先补哪项——缺铁补铁、缺钙补钙。审计也一样：四关里**命中关键词最少**的那关，就是最该补强的方向。比如说明里一个字没提安全，密钥明文、防火墙没装，补强方向就是「安全」。

**定义**：**缺失分析** = 找出四类中**命中数最少**的一类，它就是「建议补强」的方向；如果并列，按 功能 → 安全 → 数据 → 运维 的顺序取靠前的那个（程序结果才稳定）。

```python
scores = {"功能": 2, "安全": 0, "数据": 2, "运维": 0}   # 各关命中数
best = "功能"
for name in ["安全", "数据", "运维"]:       # 固定顺序，并列取靠前
    if scores[name] < scores[best]:
        best = name
print("建议补强：", best)                   # 安全（命中最少，且排在运维前面）
```

> ⚠️ 易错点：
> 1. **看「命中数」不是看「分数」**：分数已经封顶 2 分，看不出是命中 2 个还是 3 个关键词；缺失分析要用**原始命中数**比，少的才是缺的——就绪度满分 8 也可能有短板。
> 2. **并列要有固定顺序**：两个方向同样少时，不规定顺序程序每次跑的结果都不一样——按 功能 → 安全 → 数据 → 运维 固定取第一个。

## ✅ 综合验收与收官：四步走完，项目上不上得了线一目了然

**类比**：塔主最后一道总检：四关齐不齐、每关有没有具体交代、缺的有没有补强计划——全部通过才放行。审计一份情况说明，也是同一条流水线：**读进来 → 扫描计分 → 找缺失 → 兜底空内容**。

**定义**：**综合验收** = ① 读入「上线前情况说明」；② 四组关键词扫描，每类最多 2 分，算出上线就绪度（满分 8）；③ 找命中数最少的一类，给出「建议补强」；④ 说明是空的（或只有空白）时，打印「没有内容」兜底，而不是算出一个「0 分」糊弄人。四步走完，一个项目上不上得了线，一眼看穿——这就是守卫塔的结业大考，也是 w5「安全与运维」的收官之战。

```python
import io

# 模拟读入一份「上线前情况说明」（quest 里用 sys.stdin 从测试输入读）
text = io.StringIO("功能测试全部跑通，每天备份数据").read()
if not text.strip():
    print("没有内容")
else:
    t = text.lower()
    keys = [("功能", ["功能", "测试", "跑通"]),
            ("安全", ["安全", "审计", "密钥", "防火墙"]),
            ("数据", ["数据", "备份", "恢复"]),
            ("运维", ["运维", "日志", "监控"])]
    scores, total = {}, 0
    for name, words in keys:
        hit = sum(1 for w in words if w in t)
        scores[name] = hit
        total += min(hit, 2)
    print("上线就绪度：%d 分" % total)          # 满分 8
    best = "功能"
    for name, _ in keys[1:]:
        if scores[name] < scores[best]:
            best = name
    print("建议补强：%s" % best)
```

> ⚠️ 易错点：
> 1. **空输入要最先兜底**：`if not text.strip(): print("没有内容")` 要放在算分**之前**，并且算分逻辑放进 else 里——否则空说明会打出「上线就绪度：0 分」，那不是人话。
> 2. **四步顺序别乱**：先读、再算分、然后找缺失、最后才谈建议——缺失分析要建立在扫完所有四类之后，边扫边找会把漏掉的类错过。
