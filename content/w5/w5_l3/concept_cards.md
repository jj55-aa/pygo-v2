# 服务器安全——守好你的塔

## 🚪 端口最小化：塔只开一扇门

你登上「守卫塔」的城墙。这座塔曾经开满了门：正门、侧门、后门、粮仓门、密道口……安全官把大部分门全封死了，只留一扇正门供访客进出。为什么？**门越多，敌人能进来的入口就越多，防守就越难。多一扇门，就多一分被攻破的风险。**

服务器也一样。**端口（Port）就是服务器上的「门」**：每一个对外提供的服务，都要占一个端口号。网页服务占 80/443，数据库占 3306，Redis 缓存占 6379……

**端口最小化 = 只开放业务真正需要的端口，其余端口一律关闭**。上线前数一数你开了哪些端口：没有业务在用的，全关掉。能进来的「门」越少，攻击者能下手的地方就越少——这个范围叫**攻击面**，攻击面越小越安全。

```python
# 模拟：盘点服务器开放的端口，找出「多开的门」
business_ports = {80, 443}          # 业务只需要：网页(80) 和 加密网页(443)
opened = {22, 80, 443, 3306, 6379}  # 实际打开的端口
extra = opened - business_ports      # 多开的部分
if extra:
    for p in sorted(extra):
        print(f"端口 {p} 没有业务在用，建议关闭！")
else:
    print("端口已最小化，只有业务需要的门是开的")
```

> ⚠️ 新手最容易踩的坑：
> 1. **图省事把端口全开**：「说不定以后用得上」——每一个多开的端口都是给攻击者留的门。
> 2. **只记得「开」，忘了「关」**：调试用的端口（比如数据库 3306）上线后还挂着，等于把保险柜的钥匙挂在门口。
> 3. **端口最小化 ≠ 不开端口**：业务要用的 80/443 必须开，关键是「只开需要的」。

## 🧱 防火墙：塔门的守门人

门封好了，但塔的正门还开着——谁来把关？答案是**守门人：防火墙（Firewall）**。

防火墙是服务器上的一道**闸门**，它手里有一本**规则册**：哪些端口、哪些来源可以放行，哪些必须拦下，全按规则执行。合理的默认策略是**白名单思路**：规则里没写的，一律拦截。你只需要在规则册里写上业务要用的那几扇门。

⚠️ 注意：服务器系统有防火墙，云厂商后台还有一层「安全组」，它们是**两道独立的门**。只开一道，另一道还拦着，外部照样访问不了；反过来，两道都忘了关，等于门户大开。上线后要**分别核对**，再实际从外面访问一次验证。

```python
# 模拟：防火墙按规则册放行或拦截
allow = {80, 443}                    # 规则册：只放行这两扇门
def firewall(port):
    if port in allow:
        return "放行"
    return "拦截"

for p in [80, 443, 3306]:
    print(f"端口 {p}：{firewall(p)}")
```

> ⚠️ 新手最容易踩的坑：
> 1. **只开一扇门**：防火墙和安全组是两层独立配置，都要核对，缺一不可。
> 2. **规则开完不验证**：放行之后一定要从外面真实访问一次，别「我以为开了」。
> 3. **把防火墙当成万能**：防火墙管「谁进得来」，管不了「进来的人干坏事」——登录安全同样要抓好。

## 🔧 更新与补丁：及时补塔墙的裂缝

塔墙用久了会出裂缝：某处砖缝渗水、某段石墙松动。更麻烦的是——**裂缝的位置是公开的**，敌人看得到，专挑裂缝下手。不补，裂缝只会越裂越大。

软件和系统也一样会「裂」：开发者发现漏洞（Vulnerability）后，会发布**更新（Update）和补丁（Patch）**来修复。漏洞一旦被公开，攻击者就会立刻扫描全网，批量攻击**还没打补丁**的服务器——这正是「更新不及时」的杀伤力所在。

**更新与补丁 = 及时修补已知的裂缝**：操作系统、Web 服务器、数据库、你用的第三方依赖，一个都不能漏。别因为「更新要重启服务、怕麻烦」就拖着——你拖一天，敌人就多一天时间顺着裂缝爬进来。

```python
# 模拟：检查各组件的补丁状态
components = {"操作系统": "已修复", "Web 服务器": "有漏洞", "数据库": "有漏洞"}
for name, status in components.items():
    if status == "有漏洞":
        print(f"⚠️ {name} 有已公开漏洞，赶紧装补丁！")
    else:
        print(f"✓ {name} 已更新，安全")
```

> ⚠️ 新手最容易踩的坑：
> 1. **「能跑就不用更新」**：漏洞不影响「能不能跑」，影响的是「会不会被攻破」——恰恰是能跑的时候最该补。
> 2. **只更新主程序**：依赖库、基础镜像同样可能带漏洞，都要一起查、一起更。
> 3. **更新前不备份**：重要系统先备份再更新，万一更新出问题能快速回滚。

## 🔑 登录安全：不用密码，只认钥匙

塔还有一个「管理通道」：你人在城外，要通过 SSH 远程登录进塔指挥。这道门怎么守？

老办法是**密码登录**：喊一句暗号「芝麻开门」。暗号会被偷听、会被反复试（暴力破解）、还会被撞库——密码再长也有被攻破的一天。**SSH 密钥登录**换了个思路：不用暗号，改用**钥匙**。服务器里存「锁」（公钥），你的电脑上放一把独一无二的「钥匙」（私钥）。登录时钥匙和锁对上，才能进门——密码根本不参与，猜无可猜。

还有一条铁律：**默认密码必须改**。服务器、数据库、管理面板出厂都自带默认密码（比如 admin / 123456）——这些是公开常识，攻击者登录的第一件事就是试默认密码。拿到服务器的第一件事：改掉所有默认密码，能换成密钥登录就换。

```python
# 模拟：密钥登录 vs 密码登录
def login(way):
    if way == "密钥":
        return "安全：只有持钥匙的电脑能进，猜不到"
    return "风险：密码可能被偷听、被猜中、被撞库"

print("SSH 密钥登录 →", login("密钥"))
print("密码登录    →", login("密码"))

password = "admin"      # 还挂在默认密码？
if password == "admin":
    print("⚠️ 正在使用默认密码，必须马上改！")
```

> ⚠️ 新手最容易踩的坑：
> 1. **用弱密码糊弄**：123456、admin、生日——暴力破解几秒就试出来，形同虚设。
> 2. **默认密码「没人知道」就不用改**：默认密码是出厂说明里写着的公开信息，改了才算你自己的。
> 3. **密钥文件到处乱发**：私钥就是钥匙本身，拷贝给别人等于把塔的钥匙交给了别人。
