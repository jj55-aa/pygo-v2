# 系统设计——做软件前先想清楚

## 🧾 需求分析：先把「要做什么」写清楚

你走进教务楼，班主任的办公桌上堆满了学生档案：谁的分数记错了、谁转学了没删、全班平均分要一个个数……她叹了口气：「帮我想个办法吧！」

做软件之前，第一步不是写代码，而是**弄清楚用户到底要什么**——这叫**需求分析**。就像装修房子，动工前得先和设计师确认：要几间卧室、要不要书房；不问清楚就开工，装出来准不是你要的家。班主任的需求就是一张「**需求清单**」：

- **录入**：收下新学生的信息（姓名 + 分数）
- **查询**：想找某个学生时能马上找到
- **修改**：分数登错了能改过来
- **删除**：转学的学生能从档案里移除
- **统计**：全班多少人、平均分多少

```python
# 学生管理系统的需求清单（班主任版）
# 1. 录入：添加一条学生信息（姓名 + 分数）
# 2. 查询：按姓名找到学生
# 3. 修改：更新学生的信息
# 4. 删除：移除一名学生
# 5. 统计：全班人数、平均分
print("需求清单：录入 / 查询 / 修改 / 删除 / 统计")
```

> ⚠️ 新手最容易踩的坑：
> 1. **别一上来就写代码**——需求没想清楚，写出来的系统班主任不爱用：她要的是「统计」，你只做了「录入」，白忙一场还得返工。
> 2. 需求要**写下来**，别只在脑子里想。写在注释里，它就是你的第一份设计文档，后面写代码、交作业都靠它。

## 🗂️ 数据结构设计：字典装一条，列表装一柜

需求清楚了，接下来想：**信息在程序里怎么存？**这就是**数据结构设计**。

把每个学生想成一张「档案卡」，卡片上贴着标签：姓名、分数。一张卡片正好对应 Python 的**字典**——用**键（key）**给每个字段贴标签：

```python
# 一条学生记录：字典（键值对给字段贴标签）
stu1 = {"name": "小明", "score": 95}
stu2 = {"name": "小红", "score": 88}
```

一个班有几十个学生，几十张卡片不能散在地上——要放进**档案柜**，按顺序排好。Python 里这个「柜子」就是**列表**：

```python
# 多条学生记录：列表（按顺序存放）
students = [stu1, stu2]

# 遍历打印，用键取值
for s in students:
    print(f"姓名：{s['name']}，分数：{s['score']}")
```

规则一句话：**一条 = 字典，多条 = 列表**。取数据时用键 `s["name"]`，就像按标签抽档案卡，又快又不会拿错。

> ⚠️ 新手最容易踩的坑：
> 1. **键名要前后一致**：定义时用 `"name"`，取值时就不能写 `s["名字"]`，否则直接报 `KeyError`——字典只认它定义过的键。
> 2. 字典取值用**键**（`s["name"]`），不是下标（`s[0]`）——那是列表的用法。
> 3. `input()` 拿到的一律是字符串，分数要**先转成数字**再存：`int(input())`。

## 🔁 菜单循环：让系统自己「转起来」

需求有了、数据结构有了，接下来把功能「串」起来——用一个**菜单**让用户自己选：选 1 录入、选 2 退出……就像自助餐厅，菜单一直亮着，顾客报个号，服务员就做对应的菜，直到顾客说「结账走人」。

Python 里让菜单一直显示、直到用户退出，靠的就是 `while True` + `if/elif` 分支：

```python
while True:
    print("1. 录入学生")
    print("2. 退出系统")
    choice = int(input())          # 读入选项数字
    if choice == 1:
        print("开始录入学生信息")
    elif choice == 2:
        print("系统退出，再见！")
        break                      # 跳出循环，程序结束
    else:
        print("输入错误，请重新选择")
```

- `while True`：条件永远成立，菜单**一直显示**，程序不退出
- `if / elif / else`：按选项数字**分支**，选几就执行哪一段
- `break`：用户选「退出」时**跳出循环**，程序才停得下来

> ⚠️ 新手最容易踩的坑：
> 1. **`while True` 里必须有 `break`**——不然就是死循环，程序永远停不下来。
> 2. 分支要用 `elif` 而不是 `if`：写成两个 `if`，用户选 1 时「选 2 的判断」也会执行，逻辑全乱。
> 3. `input()` 拿到的是字符串，和数字比之前要 `int()` 转换；`if` / `elif` 后面别忘了冒号 `:` 和缩进。

## 📐 设计先行：先画图纸，再写代码

最后一步，也是最容易被跳过的一步：**动手前先画图纸**。盖楼不画图纸直接砌砖，墙歪了才知道；做饭不列菜谱，炒到一半忘了放盐。写程序也一样——**设计先行**：把「要做什么、数据怎么存、流程怎么走」想清楚，再用注释把骨架搭出来。

设计的顺序是固定的：**需求清单 → 数据结构 → 界面流程（菜单）→ 代码骨架**。先让骨架「能转」，再一项项往里填真功能：

```python
# 设计稿：先写注释，再写代码
# 数据：students = []        ← 列表，装学生字典
# 流程：
#   while True:
#     显示菜单
#     读选项
#     1 → 录入；2 → 退出(break)；其他 → 提示重选

# 骨架代码：先让系统「能转」，功能下一课再填
students = []
while True:
    print("1. 录入学生")
    print("2. 退出系统")
    choice = int(input())
    if choice == 1:
        print("开始录入学生信息")   # 骨架先占位
    elif choice == 2:
        break                        # 选 2 退出
```

> ⚠️ 新手最容易踩的坑：
> 1. **边写边想最容易乱**——先用注释把结构和流程写清楚，再动手敲代码。
> 2. 一次别贪多：先把「菜单能转、能退出」的**最小系统**跑通，再逐项填功能，每一步都有能运行的版本。
> 3. 设计不是一次到位的：运行中发现新问题，回头改设计很正常——改设计比改一堆乱代码便宜得多。
