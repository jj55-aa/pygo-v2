# 游戏循环——游戏的心脏

## 🎠 旋转木马：游戏就是一圈圈转

你走进「像素游乐园」的大门，第一眼看到的就是**旋转木马**：它一圈圈地转，每一圈，木马动一格、彩灯闪一次、游客看到新的景色。只要不停电，木马就永远转下去。

**游戏就是一台旋转木马**。一个游戏程序不会"跑一遍就结束"——它用 `while True` 让主循环**一圈圈转个不停**，每一圈都做同样三件事：

1. **等事件**：看看用户按了什么键、点了哪里、是不是想退出（喂木马）
2. **更新状态**：角色的位置、金币的位置、分数……把所有"会变的量"往前推一步（木马转一格）
3. **渲染画面**：把最新的状态画到屏幕上，让用户看到新的一帧（新景色出现）

这三件事循环往复，就是**游戏循环（game loop）**——游戏的心脏。没有它，画面是死的，游戏是"一张画"，不是"一个游戏"。

木马转多快也有讲究：**帧率（FPS，Frames Per Second）** = 每秒刷新多少张画面。60 FPS 就是每秒画 60 张、流畅丝滑；10 FPS 就像放幻灯片，一卡一卡的。真游戏里用 `pygame.time.Clock().tick(60)` 把帧率控制在每秒 60 圈。

```python
# 真实的 Pygame 游戏循环（在本地电脑上运行）：
# import pygame
# pygame.init()
# while True:                          # 旋转木马：一圈又一圈
#     for event in pygame.event.get(): # ① 等事件：用户按了什么？
#         ...
#     player.update()                  # ② 更新状态：位置、分数往前推一步
#     screen.blit(...)                 # ③ 渲染画面：把最新状态画上去
#     pygame.display.flip()            # ④ 刷新屏幕：让画面真正显示出来

# 逻辑模拟（判题环境可运行）：旋转木马转 3 圈
for i in range(3):
    print(f"第 {i + 1} 圈：等事件 → 更新状态 → 渲染画面 → 刷新")
```

> ⚠️ 新手最容易踩的坑：
> 1. **游戏循环要 `while True`**：普通程序跑一遍就结束，游戏必须"一直转"，直到玩家主动退出。
> 2. **每一帧都要刷新**（`display.flip()`）：光"画"不"刷新"，用户看到的永远是旧画面，游戏就像卡住了。

## 🎮 Pygame：造游戏的百宝箱

旋转木马得有人造。在 Python 里造游戏，最常用的工具箱是 **Pygame**——一个**第三方游戏库**：窗口、图形、声音、事件这些底层麻烦事它都封装好了，你只管写游戏逻辑。

**Pygame 不是标准库，装好 Python 并没有它**——要先用 pip 安装一次：

```
pip install pygame
```

装好之后，"开张"只需三步：

1. `import pygame`——把工具箱搬进来
2. `pygame.init()`——初始化所有模块（开机自检）
3. `screen = pygame.display.set_mode((800, 600))`——创建 800×600 的游戏窗口

然后是 `while True` 的游戏循环骨架。Pygame 里常用的模块：

| 模块 | 干什么 |
| --- | --- |
| `pygame.display` | 访问屏幕/窗口（set_mode 开窗口、flip 刷新） |
| `pygame.event` | 管理事件（get 取出按键、点击、关窗） |
| `pygame.draw` | 绘制形状（画圆、画矩形） |
| `pygame.sprite` | 精灵——会移动的图像（下一课的主角） |
| `pygame.time` | 时钟——控制帧率（tick(60)） |

```python
# 安装（在你的电脑终端里运行一次）：
# pip install pygame

# 真实的 Pygame 骨架（在本地电脑上运行）：
# import pygame
# pygame.init()                                 # ① 初始化所有模块
# screen = pygame.display.set_mode((800, 600))  # ② 创建 800×600 的窗口
# pygame.display.set_caption("像素游乐园")       # ③ 设置窗口标题
# while True:                                   # ④ 游戏循环，一圈圈转
#     ...

# 逻辑模拟（判题环境可运行）：记住开张三步曲
print("① pip install pygame 安装游戏库")
print("② pygame.init() 初始化所有模块")
print("③ set_mode((宽, 高)) 创建游戏窗口")
```

> ⚠️ 新手最容易踩的坑：
> 1. **pygame 要 `pip install pygame` 才能用**：它和 math、random 不一样，不是自带的标准库。没装就 `import pygame` 会报 `ModuleNotFoundError`。
> 2. **判题环境（Pyodide）没有 pygame**：`import pygame` 会报错，也弹不出游戏窗口——概念照讲，动手题用 input/print 验证游戏逻辑。

## ⌨️ 事件与状态：按键改变世界

游戏为什么"动"？因为它会**响应你**。你按一下右键，角色就往右走——这背后是两样东西在配合：

- **事件（event）**：用户的操作。按键、鼠标点击、关闭窗口……游戏循环第一件事就是**处理事件**：用 `pygame.event.get()` 把这一帧发生的事一件件取出来，看是按键、点击还是关窗。
- **状态（state）**：游戏里所有**会变的量**。角色坐标、分数、金币位置、生命值……渲染画的不是"画面"，而是**状态**。

两者的关系是一条链：**按键 → 产生事件 → 修改状态 → 下一帧渲染 → 画面跟着变**。按右键：产生 `KEYDOWN` 事件 → 角色 x 坐标 +5 → 下一帧渲染时角色往右挪了 5 像素。画面本身不会动，动的是状态，渲染只是把状态**如实画出来**——这就是"游戏动起来"的全部秘密。

```python
# 真实的 Pygame 事件处理（在本地电脑上运行）：
# for event in pygame.event.get():
#     if event.type == pygame.QUIT:        # 点了窗口的关闭按钮
#         running = False
#     elif event.type == pygame.KEYDOWN:   # 按下了某个键
#         if event.key == pygame.K_RIGHT:
#             player_x += 5                # 状态改变：角色右移 5 像素

# 逻辑模拟（判题环境可运行）：按键 → 改状态 → 画面跟着变
pos = 0
keys = ["右", "右", "左"]
for k in keys:
    if k == "右":
        pos += 5          # 更新状态：角色往右 5 像素
    elif k == "左":
        pos -= 5
    print(f"按下「{k}」→ 角色位置更新为 {pos}")   # 渲染：画面跟着变
```

> ⚠️ 新手最容易踩的坑：
> 1. **每圈都要 `pygame.event.get()`**：事件是一帧一帧"取"的，写在循环外只取一次，按键就全丢了。
> 2. **状态要不断更新**：分数、位置这些要写进游戏循环里每帧更新；只在循环外算一次，画面就永远不变。
> 3. 真游戏里别用 `input()` 等用户输入——它会把游戏循环**卡停**，木马不转了。input 只是本课"逻辑模拟"用的道具。

## 🧪 逻辑模拟：没有窗口也能写游戏

现在的判题环境（Pyodide）**没有 pygame，开不了真实的游戏窗口**。那本课怎么练？——**只练游戏的心脏：逻辑**。

思路是把"游戏循环"拆成判题环境能跑的样子：

- 用 **`input()` 模拟"每一帧的事件"**：每读一个数字，就当游戏循环转了一圈
- 用 **`print()` 模拟"画面刷新"**：把当前状态（分数、位置）打印出来，就是"渲染"

这样写出来的代码，就是游戏引擎的核心：**分数累加、循环条件、碰撞判断**这些逻辑，和真 pygame 里跑的一模一样。逻辑跑通了，装进真 pygame 窗口、配上画面，就是能玩的游戏——**画面是外壳，逻辑才是心脏**。

```python
# 判题环境没有 pygame：用 print 模拟「每一帧的画面刷新」
# 模拟一局 3 帧的小游戏：1 = 接到金币 +10 分，0 = 没接到
score = 0                    # 游戏状态：初始分数
events = [1, 0, 1]           # 模拟 3 帧的事件序列
for e in events:
    if e == 1:
        score += 10          # 更新状态：这帧接到了金币，加分
    print(f"本帧事件 {e} → 画面刷新：当前分数 {score}")
```

> ⚠️ 新手最容易踩的坑：
> 1. **判题环境里别写 `import pygame`**：会报 `ModuleNotFoundError`。要练的 pygame 知识写在注释里供参考，能运行的代码是 input/print 的**逻辑模拟**。
> 2. **分数/位置更新要写在循环里面**：写在循环外，状态永远不会变，分数永远是初始值。
> 3. 模拟时**一个事件对应一帧**：每读一个 input 就相当于游戏循环转了一圈——别在一次 input 里塞多个事件。
