# 独立挑战——像素游乐园的结业大考

## 🎮 游戏全景：循环 + 精灵 + 事件 + 状态

游乐园中央那台街机，屏幕上的画面从来不是「一张画」，而是**一秒 60 帧的连续快照**。每一帧，机器都干同一件事：先「听」玩家按了什么按钮（事件），再「算」游戏变成什么样（更新状态），最后「画」出来给玩家看（绘制画面）——就像旋转木马转一圈 = 一帧：先看游客按了什么，再决定木马转到哪，最后让游客看到新位置。

**游戏 = 循环 + 精灵 + 事件 + 状态**。精灵（sprite）是画面里的角色和物体（苹果、接盘）；事件（event）是玩家或系统发出的一次动作（按方向键、苹果落下来）；状态（state）是游戏「现在怎么样」的全部数据（分数、生命、位置）。这三样靠**游戏循环**串起来：`处理事件 → 更新状态 → 绘制画面`，循环往复直到游戏结束。

判题环境（Pyodide）没有 pygame 窗口，但**核心循环逻辑可以完整保留**：事件用 `sys.stdin` 输入模拟、画面用 `print` 输出模拟——循环骨架一模一样：

```python
import sys

# 游戏循环的骨架：事件（输入）→ 状态（更新）→ 输出（绘制）
x = int(sys.stdin.readline())          # 事件：玩家把接盘放到 x 位置
apples = [int(v) for v in sys.stdin.read().split()]   # 事件：一串苹果落点

score = 0                              # 状态：分数（初始化在循环外！）
life = 3                               # 状态：生命
for ax in apples:                      # 循环：一个苹果 = 一帧
    if abs(ax - x) < 3:                # 更新：碰撞判定
        score += 10                    # 接住：分数 +10
    else:
        life -= 1                      # 漏接：生命 -1
print(score, life)                     # 输出（绘制）
```

> ⚠️ 易错点：循环的**顺序别搞反**——先处理事件（读输入），再更新状态（算分数/生命），最后输出；状态变量（score/life）要**初始化在循环外面**，放里面会被每帧重置，永远算不对；「精灵」在判题环境里只是数字坐标，别想着画图，先把「事件 → 状态 → 输出」的循环跑通。

## 🕹️ 事件循环模拟：input 就是「玩家按的按钮」

街机的手柄上每按一下，机器就收到一条「事件」。判题环境没有键盘、没有窗口，用什么模拟事件？——**每一行输入就是一次玩家操作**：`sys.stdin` 一行行把事件喂给程序，`for` 循环逐条处理，等价于真实 Pygame 里 `pygame.event.get()` 取出的事件队列。

**事件（event）** = 玩家或系统发出的一次动作。真实游戏里是「按下方向键」「苹果碰到地面」；这里变成「第一行：接盘位置」「第二行：苹果数量」「之后每行：一个苹果落点」——**读一行、处理一行**，就是游戏循环里的「事件处理」。

```python
import sys

text = sys.stdin.read().split()        # 一次读完全部事件（按空白切分）
x = int(text[0])                       # 事件 1：玩家把接盘放在 x
n = int(text[1])                       # 事件 2：本局有 n 个苹果
for i in range(n):
    ax = int(text[2 + i])              # 事件 3、4……：第 i 个苹果落在 ax
    print("苹果落在", ax)              # 逐条处理：一帧处理一个事件
```

> ⚠️ 易错点：读进来的**全是字符串**，不 `int()` 就直接比较大小，`"8" < 5` 永远不会成立——苹果永远「接不住」；事件要**按顺序读**（接盘位置 → 苹果数量 → 落点），顺序乱了状态就全乱；输入行数不够时（`text[2+i]` 取不到）抛 **IndexError**——这就是「事件没了」，要用 try/except 兜底，别让程序当场崩。

## 📊 状态更新：分数、生命、碰撞判定

游乐场的记分牌：每接住一个苹果，记分牌「得分」+10；每漏一个，生命灯 -1。**状态就是记分牌上的数字**——游戏每一帧都要读它、改它，最后把它画给玩家看。

**状态（state）** = 游戏「现在怎么样」的全部数据（分数 score、生命 life、位置 x）。游戏循环每帧根据事件更新状态；更新里最关键的一步是**碰撞判定**——苹果到底接没接住？规则就一句：**接住 = |落点 - 接盘| < 3**（两者距离严格小于 3，算碰到）。

```python
score = 0
life = 3
for ax in [3, 7, 8]:                   # 苹果依次落在 3、7、8
    if abs(ax - 5) < 3:                # 碰撞判定：|落点 - 接盘| < 3
        score += 10                    # 接住：分数 +10
    else:
        life -= 1                      # 漏接：生命 -1
print(score, life)                     # 20 2
```

> ⚠️ 易错点：**`abs()` 千万别漏**——落点在接盘左边时（3 比 5 小）`5 - 3` 算出来是负数，负数 < 3 恒成立，苹果会「全部接住」；边界要写**严格小于**：`< 3` 意味着距离正好 3 **不算**接住；score/life 的初值（0 和 3）初始化在循环外，且两件事别互相覆盖——加分的不减命、减命的不加分。

## 🏁 胜负与输出：游戏结束条件

游乐场有关门时间：生命灯全部熄灭，机器「哔」一声停机——**这就是游戏结束**。程序里，结束条件（`life == 0`）一旦满足，就 `break` 提前跳出循环，把结算结果打出来。

**游戏结束** = 满足结束条件（生命归 0）后循环提前终止、输出结算。**胜负输出** = 用 `print` 把最终状态翻译成人话——「得分X，生命Y」。

```python
score = 0
life = 3
apples = [0, 20, 30]
for ax in apples:
    if abs(ax - 10) < 3:
        score += 10
    else:
        life -= 1
        if life == 0:                  # 结束条件：生命耗尽
            break                      # 提前停止：后面的苹果不再处理
print("得分%d，生命%d" % (score, life))   # 得分0，生命0
```

> ⚠️ 易错点：**漏写 `break`**——生命会继续减成 -1、-2，结算数字离谱（提前停止要「停」得干净）；结束判定要放在**漏接的 else 分支里**（接住不扣命，自然也不会触发结束）；输出格式要和题目**一字不差**——中文标点「，」、`%d` 占位符，错一个字符判题 diff 就会提示「内容与空格不同」。
