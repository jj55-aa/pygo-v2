# 精灵与碰撞——让游乐园的角色"活"起来

## 🧸 精灵是什么——戏台上的"提线木偶"

像素游乐园中央摆着一台**提线木偶戏台**。一个木偶由两样东西组成：**模样**（它是小丑、是小猫、是骑士）和**站位**（它站在戏台的哪个位置）。模样和站位分开，木偶就演不了戏——只有模样不知道画在哪，只有站位不知道画什么。

游戏里的**精灵（Sprite）**就是这台戏台上的木偶：**一张图片（模样）+ 一个位置坐标（站位）**。Pygame 里，角色、树木、金币、子弹……凡是会动、会被碰到的东西，都是一个精灵。Pygame 专门准备了 `pygame.sprite.Sprite` 这个类来装它们——把"图片"和"位置"打包在一起，还自带"画到屏幕上"的接口。

```python
# 真实 Pygame 里的精灵（在本地电脑上运行）：
# import pygame
# class Player(pygame.sprite.Sprite):
#     def __init__(self):
#         super().__init__()
#         self.image = pygame.image.load("player.png")  # 模样：图片
#         self.rect = self.image.get_rect()             # 站位：矩形 rect
#         self.rect.x = 100                             # 初始 x 坐标
#         self.rect.y = 200                             # 初始 y 坐标

# 判题环境没有 pygame——用字典模拟"木偶"（模样 + 站位）：
player = {"image": "小丑.png", "x": 100, "y": 200}
print(player["image"], "站在", player["x"], player["y"])
```

> ⚠️ 新手最容易踩的坑：
> 1. **精灵 = 图片 + 位置，缺一不可**：只有图片没有位置，不知道画在哪；只有位置没有图片，屏幕上是一块空白。
> 2. Pygame 里精灵的"站位"通常是一个**矩形 rect**（位置 + 大小），画图、碰撞检测全靠它。
> 3. **判题环境（Pyodide）没有 pygame**——概念照讲，本课的动手题（code/quest）全部用 `input`/`print` 验证精灵背后的"坐标与碰撞逻辑"。

## 🎯 坐标与移动——x 往右、y 往下

屏幕就是一张网格纸，**左上角是原点 (0, 0)**：x 越大越靠右，y 越大越**往下**。注意！数学课上 y 是往上长的，游戏屏幕里 y 是往下的——坐标越往下越大。

**移动精灵 = 改变它的坐标，再刷新屏幕**。游戏循环每转一圈（一帧）：读输入（按了哪个方向键）→ 改坐标 → 把屏幕重新画一遍，精灵就"活"了。往右走就 **x 加**，往左走就 **x 减**，往下跳就 **y 加**，往上跳就 **y 减**。

```python
# 木偶的初始站位
x = 100
y = 200
step = 10

# 按了一次「右方向键」：x 加 step，y 不动
x = x + step          # 也可以写成 x += step
print("木偶现在在", x, y)   # 输出：木偶现在在 110 200
```

> ⚠️ 新手最容易踩的坑：
> 1. **坐标从左上角 (0, 0) 起算，y 向下增大**——别按数学课的习惯把 y 当"向上"，否则跳理会变成往地底钻。
> 2. **移动 = 改坐标 + 刷新屏幕**：只改坐标不刷新，画面还是老样子。判题环境里没有屏幕，就验证坐标数字的变化。
> 3. 往右走是 **x 加**、往左走是 **x 减**——方向搞反，角色会"倒着走"。

## 💥 碰撞检测——"碰到"是道数学题

两个木偶"碰到"了吗？游戏里用**数学**来回答，两种最常用的判法：

- **矩形相交**：把每个精灵用一个矩形框住（Pygame 里是 `rect.colliderect(另一个rect)`），两个矩形有重叠就是碰撞。适合"大方块"的角色。
- **距离判定**：取两个精灵的中心点，算两点距离，**距离小于某个阈值就认为碰到**。适合小球、子弹、苹果这类"点状"目标。

两点距离公式就是勾股定理：`d = √((x1-x2)² + (y1-y2)²)`。阈值自己定，比如"距离小于 3 就算碰到"。

```python
# 两个小球精灵的中心坐标
x1, y1 = 2, 3
x2, y2 = 2, 6

d = ((x1 - x2) ** 2 + (y1 - y2) ** 2) ** 0.5   # 距离 = 3.0
if d < 3:               # 距离 < 阈值 3，视为碰到
    print("碰撞！")
else:
    print("没碰到")      # 距离正好等于 3 → 不算碰（严格小于）
```

> ⚠️ 新手最容易踩的坑：
> 1. **碰撞 = 距离小于阈值（`d < 3`），不是小于等于**——正好等于阈值时不碰。这是踩坑率最高的一条！
> 2. 判题环境没有 pygame，`colliderect` 跑不了——本课全部用**坐标数学（两点距离）**模拟碰撞。
> 3. 想省掉开方、直接比平方距离时小心：`(dx² + dy²) < 3` 和 `d < 3` 不是一回事——要么老老实实开方，要么把右边的阈值也平方（`< 9`）。

## 🍎 得分与生命——游戏的小算盘

每台游戏都挂着一个小算盘：**得分**记你玩得多好，**生命**记你还剩几次机会。接苹果游戏里：苹果被接盘接住（碰撞判定通过）→ **得分 +1**；苹果落地没人接 → **生命 -1**；生命降到 0 → 游戏结束。

判定逻辑是纯数学——引擎只问"这个苹果算接住还是漏掉？"，记数的活交给变量：`score += 1` 加分，`lives -= 1` 扣命。

```python
score = 0     # 得分：从 0 开始
lives = 3     # 生命：从 3 开始

# 模拟一局：3 个苹果依次被判定为「接住 / 漏掉 / 接住」
for caught in [True, False, True]:
    if caught:          # 碰撞判定通过 → 得分 +1
        score += 1
    else:               # 没接住 → 生命 -1
        lives -= 1

print("得分：", score, "剩余生命：", lives)   # 得分： 2 剩余生命： 2
```

> ⚠️ 新手最容易踩的坑：
> 1. 得分和生命是**普通变量**，用 `+= 1` / `-= 1` 增减；写成 `score = 1` 会把分数清零重来。
> 2. "漏掉"是"接住"的**反义**：接住条件是 `|落点 - 接盘| < 3`，漏掉就是 `|落点 - 接盘| >= 3`（或者直接 `else`）。
> 3. 游戏结束的判断（`if lives <= 0`）平时放在**游戏循环**里；判题环境没有循环和窗口，我们把"判定 + 计数"这段逻辑抽出来单独验证。
