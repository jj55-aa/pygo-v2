# 数据库设计——看懂 AI 建的表

## 🗄️ 表就是档案柜：字段是列，记录是行

建造工地的材料间里立着一排档案柜：一个柜子只放一种材料——钢筋柜只放钢筋，水泥柜只放水泥。数据库里的**表（table）**就是这样的档案柜：**一张表只存一类数据**。比如「工人表」只存工人、「材料表」只存材料。

打开一个档案柜，里面是这样组织的：

- **字段（field）= 列**：柜子里的分类格——「姓名」「工位」「联系电话」就是字段，描述一条数据的一种**属性**
- **记录（record）= 行**：柜子里的一页页档案——「张三、3 号塔吊、138xxxx」就是一条记录，是**一条完整的数据**

用 Python 模拟一张「工人表」：

```python
# 用列表套字典模拟一张「工人表」
workers = [
    {"姓名": "张三", "工位": "3 号塔吊", "联系电话": "13800001111"},
    {"姓名": "李四", "工位": "搅拌站", "联系电话": "13800002222"},
]
print("表名：工人表")
print("字段（列）：", list(workers[0].keys()))
for w in workers:
    print("记录（行）：", w)
```

> ⚠️ 新手最容易踩的坑：
> 1. **字段是「列」，记录是「行」**——别搞反！字段描述「一类属性」（姓名、年龄），记录是一条「完整数据」（一个具体的工人）。
> 2. **一张表只放一类数据**：工人表里塞进「今天买了什么材料」，时间一长就越存越乱。

## 🪪 主键：每行数据的身份证

档案柜里的档案很容易弄混：工地上有两个「张三」怎么办？靠名字分不清。所以每份档案都编一个**编号**——`1 号张三`、`2 号张三`，一看编号就知道是谁。

数据库里也有同样的东西：**主键（primary key）**。它是表里用来**唯一标识每一行记录**的字段，就像每行数据的**身份证号**：

- **每行一个、不能重复**——同一张表里不允许出现两个相同的 id
- **不能为空**——每行都得有身份证
- 最常见的起名方式：字段名就叫 **`id`**（英文）或 **`编号`**（中文）

用 Python 模拟：给每条记录发一张「身份证」，检查有没有重号：

```python
workers = [
    {"id": 1, "姓名": "张三", "工位": "3 号塔吊"},
    {"id": 2, "姓名": "张三", "工位": "搅拌站"},   # 同名不同人，靠 id 区分
]
ids = [w["id"] for w in workers]
print("所有 id：", ids)
print("id 有重复吗：", len(ids) != len(set(ids)))
```

> ⚠️ 新手最容易踩的坑：
> 1. **主键 = 每行的身份证**：它唯一、不能重复、不能为空——不是随便一个普通字段。
> 2. **没有主键的表很难用**：想改某一行数据，都不知道该定位哪一行，就像档案没有编号，只能一页页翻。

## 📐 设计规范：类型合理、命名清晰、不把一切塞一张表

工地上分材料有规矩：钢筋、水泥、砖头分开放，每个格子的标签写清楚，格子里放对类型的东西。数据库设计也有三条基本规范：

1. **字段类型合理**：数字就放数字（`age INTEGER`），文本就放文本（`name TEXT`）——别把年龄存成「十八岁」这种文本，也别把手机号存成数字（前导 0 会丢）
2. **命名清晰**：字段名一看就懂——`user_name`、`phone`，而不是 `aaa`、`data1`、`字段2`
3. **不把一切塞一张表**：用户、订单、商品是三类数据，就该拆成三张表；全部塞一张大表，改一个字段拖累全部

用 Python 对比「混乱设计」和「规范设计」：

```python
# 混乱：一张表塞所有东西，字段名看不懂
messy = {"data1": "张三", "data2": "3 号塔吊", "备注2": "买钢筋 10 吨"}

# 规范：拆成两张表，字段名清晰，类型合理
worker = {"id": 1, "name": "张三", "station": "3 号塔吊"}
material = {"id": 101, "name": "钢筋", "quantity": 10, "unit": "吨"}
print("工人表：", worker)
print("材料表：", material)
```

> ⚠️ 新手最容易踩的坑：
> 1. **「类型合理」≠「随便存」**：手机号、编号这类「像数字但不是数字」的，存成文本更安全。
> 2. **拆表不是拆得越碎越好**：核心是「一类数据一张表」，别为了凑数量硬拆。

## 🔍 看懂 AI 建的表：从建表语句看结构

在建造工地上，AI 助手给你递来一张「施工图纸」——数据库的建表语句。你要学会**看图**：从一段 `CREATE TABLE` 里读出「这张表存什么、有哪些字段、主键是谁」。

建表语句长这样，一行一个字段，从前往后是：**字段名 → 类型 → 额外说明**：

```sql
CREATE TABLE workers (
  id INTEGER PRIMARY KEY,     -- 主键：每行的身份证
  name TEXT,                  -- 姓名：文本
  age INTEGER,                -- 年龄：整数
  station TEXT                -- 工位：文本
);
```

读这张图，三步走：

1. **表名**：`CREATE TABLE workers` → 这张表叫 `workers`（工人表）
2. **字段**：括号里列了 `id`、`name`、`age`、`station`——就是这张表的 4 个列
3. **主键**：`id INTEGER PRIMARY KEY` → 字段 `id` 是主键（`PRIMARY KEY` 就是「主键」的意思）

用 Python 模拟「看图」：从建表语句里把字段名抠出来，并找到主键：

```python
sql = "CREATE TABLE workers(id INTEGER PRIMARY KEY, name TEXT, age INTEGER)"
# 取出括号里的内容，按逗号拆成一个个字段描述
fields_part = sql[sql.find("(") + 1 : sql.rfind(")")]
fields = [f.strip() for f in fields_part.split(",")]
names = [f.split()[0] for f in fields]          # 每个字段描述的第一个词 = 字段名
pk = [f for f in names if f.lower() == "id"]    # 主键字段通常叫 id
print("字段：", names)
print("主键：", pk)
```

> ⚠️ 新手最容易踩的坑：
> 1. **`PRIMARY KEY` 是主键的标志**：看到 `id INTEGER PRIMARY KEY` 才知道主键是 `id`——别把每个字段都当主键。
> 2. **看到没有主键的表要警惕**：AI 建的表如果没有任何字段叫 `id` 或 `编号`，多半漏了主键，让它补上。
