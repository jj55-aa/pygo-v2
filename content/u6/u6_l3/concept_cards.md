# 防御式编程——给代码穿上防弹衣

## 🛡️ 防御式编程：先假设输入会捣乱

排雷工坊的教官有句口头禅：**「进来的每段输入，都先当它是雷。」** 用户可能输错数字、可能输中文、可能啥都不输——不防御的代码，一遇到坏输入就当场崩给你看。

**防御式编程（defensive programming）** = 写代码时先假设会出错，提前校验或用 try/except 兜底，让程序在坏输入面前不崩溃、给友好提示。这就是「排雷工坊给每段代码穿防弹衣」。

```python
# 不防御：输入一捣乱，程序直接崩
n = int(input())
print(100 / n)

# 防御式：先假设 n 可能是 "abc"、可能是 0
try:
    n = int(input())
    print(100 / n)
except ValueError:
    print("请输入数字")
except ZeroDivisionError:
    print("除数不能是 0")
```

> ⚠️ 易错点：防御 ≠ 把整段程序都塞进 try。要**把「会出错的操作」（转数字、除法）和「业务逻辑」（后面的计算）分开**——try 只包可能出错的那几行，哪里出错、怎么补救，一眼就能看清。

## 🧨 输入校验：别让坏数据进门

工坊大门有安检——每件行李先过扫描仪，可疑物品直接拦下。**输入校验**就是这个安检：在使用数据之前，先确认它长什么样。

`input()` 拿到的永远是字符串，`int(input())` 想把不是数字的内容转整数，会抛 **ValueError**——程序当场崩：

```python
s = input()              # 不管用户输什么，s 都是字符串
if s.isdigit():          # 校验：全是数字才放行
    n = int(s)           # 校验通过，再转数字使用
    print("你输入的是", n)
else:
    print("请输入数字")    # 校验失败，友好提示
```

> ⚠️ 易错点：`int("abc")` 会抛 ValueError 让程序崩；`"12".isdigit()` 是 True，但 `"-3".isdigit()` 是 False——isdigit 不认负数。**先校验、再使用**，数据才安全；输入可能有负数时，用 try/except 更通用。

## 🪂 优雅降级：出错也别摔死

电梯坏了，别让乘客悬在半空——给一句人话提示，改走楼梯。程序也一样：出错时不崩溃，而是**降级**到预先准备好的友好方案。

**优雅降级（graceful degradation）** = 用 try/except 捕获异常，出错时执行补救（友好提示 / 默认值），程序继续活着：

```python
try:
    n = int(input())
    print(100 / n)
except ValueError:
    print("请输入数字")          # 转数字失败 → 提示
except ZeroDivisionError:
    print("除数不能是 0")        # 数学错误 → 提示
```

> ⚠️ 易错点：**不要写裸 `except:`**——它会吞掉一切异常（包括你代码里的 bug），出错时静默无提示，排错时一脸懵。要写**具体的异常类型**：`except ValueError`、`except ZeroDivisionError`，只兜该兜的错。

## 🔍 assert 断言：开发期的前置条件检查

教官出发前检查装备：「子弹带够了吗？地图带了吗？」不合格就地打回——**早发现，早修复**。

**assert（断言）** = 检查前置条件：条件成立啥也不做；**条件不成立，立刻抛 AssertionError**，程序停下。它是开发期的「哨兵」，帮你尽早暴露 bug：

```python
score = int(input())
assert 0 <= score <= 100, "分数必须在 0~100 之间"   # 前置条件
print("分数合法")          # 条件不成立，这行不会执行
```

> ⚠️ 易错点：assert 不是给用户的错误处理——它是**开发期防线**（正式运行时可能被 `-O` 优化掉）。给用户看的友好提示，还是要用 try/except 或输入校验兜底。
