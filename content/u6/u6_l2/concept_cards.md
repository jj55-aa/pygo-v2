# 调试技巧——学会读报错，做排雷高手

## 🔍 报错就是探雷器的"滴滴声"

排雷工坊的老兵听到探雷器"滴滴"响，不但不慌，反而眼睛一亮——滴滴声告诉他**地雷就在脚下**。Python 的报错信息（traceback）就是你的探雷器：它不骂你，它在精确地告诉你"雷埋在哪一行、是什么型号"。

一次完整的报错长这样：

```
Traceback (most recent call last):
  File "<pygo>", line 2, in <module>
    print(x)
NameError: name 'x' is not defined
```

**读报错三步法（从下往上读）**：

1. **先看最后一行**：错误类型 + 原因。`NameError: name 'x' is not defined` → 名字 x 没定义。
2. **再往上找 `File "...", line N`**：出错在**第几行**。
3. **看那一行代码**：结合错误类型想"为什么错、怎么改"。

> ⚠️ 易错点：
> - **别从第一行开始读**——traceback 顶部是"调用过程"，**最后一行才是错误根源**。
> - 行号、错误类型、出错代码三样缺一不可，只看一样容易猜错。
> - 修完一个错再跑可能还有下一个——这很正常，**一次排一颗雷**。

## 💣 高频报错认脸大会

工坊墙上贴着常见地雷的"通缉令"。每种雷长什么样、怎么拆，记下这张表：

| 报错 | 什么时候出现 | 一句话修法 |
| --- | --- | --- |
| `NameError` 名字未定义 | 用了没赋值的变量/函数名，或拼写错误 | 先赋值再用；检查拼写和大小写 |
| `SyntaxError` 语法错误 | 括号/引号没配对、漏了冒号、用了中文标点 | 补全符号，中文标点全换成英文半角 |
| `IndentationError` 缩进错误 | if/for/def 的代码块忘了缩进 | 冒号后的代码块统一按 Tab 缩进 |
| `IndexError` 下标越界 | 列表/字符串的下标超出范围 | 下标从 0 数，最大是 len-1 |
| `KeyError` 键不存在 | 字典取了一个不存在的键 | 用 in 判断，或 d.get(键, 默认值) |
| `TypeError` 类型不匹配 | 字符串和数字直接相加等 | 用 int()/str() 转成同类型 |
| `ValueError` 值不合法 | 把 "abc" 之类转成整数 | 确认要转的内容是纯数字 |

```python
print("年龄" + 18)          # TypeError：字符串不能直接 + 数字
print("年龄" + str(18))     # 修复：先 str() 转成字符串

scores = [90, 85]
print(scores[2])            # IndexError：只有下标 0、1，没有 2

info = {"name": "小明"}
print(info["age"])          # KeyError：字典里没有 age 这个键

n = int("abc")              # ValueError：转整数失败
```

> ⚠️ 易错点：
> - **中文标点**是 SyntaxError 的头号嫌疑人：`print（"你好"）` 的括号是中文的，Python 不认。
> - **下标从 0 开始**：n 个元素的列表，最后一个的下标是 n-1，不是 n。
> - **input() 拿到的一律是字符串**：不转 int() 就做算术，必报 TypeError。

## 🖨️ print 调试法：在关键位置放探针

看不清雷区地下有什么，老兵会插一根探针看土质。**print 调试法**就是往代码里插探针：在关键位置打印变量的值，看程序**走到哪一步、数据变成什么样**。

这段"总价计算器"跑起来不对劲（结果输出了 "55"，应该是 10）：

```python
price = input("价格：")
print("price 是：", price, type(price))   # 探针①：price 到底是什么类型？
count = 2
total = price * count
print("total 是：", total)                 # 探针②：total 算出来是多少？
```

跑一下，探针①立刻现出原形：`price 是： 5 <class 'str'>`——**price 是字符串**！字符串 × 2 得到 "55"，问题找到了：忘了 int() 转换。把它改成 `price = int(input("价格："))` 再跑，输出就是 10 了。

> ⚠️ 易错点：
> - 探针要插在**可疑步骤之前**，不是之后——错误发生前就要看到变量的值。
> - 调试完记得**删掉或注释掉探针**，别让 print 留在最终代码里。

## ✂️ 二分注释法：每次把雷区砍一半

整片雷场不知道地雷在哪？老兵从不一块砖一块砖地找——他先判断**雷在左半还是右半**，把范围砍半，再砍半，几次就锁定了。**二分注释法**就是这个思路：

1. 把代码**从中间分成两半**，注释掉**前一半**，运行。
2. **不报错了** → 雷在被注释掉的那一半里；**还报错** → 雷在留下的后一半里。
3. 在有问题的那一半里**继续一分为二**，重复，直到锁定那一行。

```python
# 嫌疑代码：算两个数的和与平均值
a = 3
b = 5
total = a + b
avg = total / 2
print(total)
print(avrg)      # 拼写错误：avrg → NameError 的雷
```

比如先把后半段（第 5~6 行）注释掉，运行不报错了 → 雷就在后半段；在后半段里继续砍半，很快锁定第 6 行的 `avrg` 拼错了，应该改成 `avg`。

**调试心态三条军规**：
1. **先读报错再动手**——报错信息已经把方向告诉你了，别当没看见就乱改。
2. **一次只改一处**，改完立刻运行验证；一次改三处，错了都不知道是哪处引起的。
3. **报错不是失败，是线索**——排掉一颗雷，你就更强一分。

> ⚠️ 易错点：
> - 别"盲改"：不读报错、凭感觉乱试，越改越乱。
> - 注释要整行加 `#`，别只删一半留下语法错误。
