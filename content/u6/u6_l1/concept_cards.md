# 异常处理——给代码穿上防弹衣

## 🧨 程序为什么会"爆"？——认识异常

想象你走进"排雷工坊"：地面下埋着地雷，你小心翼翼地往前走，一切正常——直到"咔嚓"一声，你踩到了雷。

程序也是这样。**平时跑得好好的，一旦遇到它处理不了的情况（比如 `10 / 0`、把 `"abc"` 当数字转换），就会"踩雷"——抛出一个异常（Exception），然后当场崩溃退出**，后面的代码一行都不执行。

```python
print("排雷工坊开工！")
print("10 ÷ 2 =", 10 / 2)   # 正常区域，顺利通过
print("10 ÷ 0 =", 10 / 0)   # 踩雷！除数为 0，程序当场崩溃
print("后面的代码不会执行了")
```

运行后会看到一行红色报错：`ZeroDivisionError: division by zero`。报错信息就像**排雷探测器**：左边告诉你踩了什么雷（异常类型），右边告诉你雷是怎么响的（错误原因）。注意看：最后一行 `print` 永远没机会执行——**程序在踩雷那一刻就停了**。

> ⚠️ 新手最容易踩的坑：
> 1. **异常是"运行到一半"才爆的**，不是写代码时的语法错误。程序不会自动跳过出错的代码继续跑。
> 2. 报错信息不是坏消息，它是探测器！**先读异常类型，再看错误信息**，才知道怎么拆雷。

## 🛡️ try/except：给代码穿上防弹衣

知道哪儿埋雷还不够，关键是要**活着走过去**。排雷工兵会穿上防弹衣：踩到雷也不怕，最多"砰"一下，人没事。

Python 的**防弹衣**就是 `try / except`：

```python
try:
    num = int(input("请输入一个数字："))
    print("10 ÷", num, "=", 10 / num)
except ValueError:
    print("这不是数字，防弹衣挡住了！")
except ZeroDivisionError:
    print("除数不能为 0，防弹衣挡住了！")
```

- `try:` 块：**试探着执行**——把可能踩雷的代码放进来
- `except 异常类型:`：**救援方案**——踩到对应类型的雷，就跳到这里执行，程序不崩溃
- 多个 `except` 可以**接龙**，一种异常配一个方案

> ⚠️ 新手最容易踩的坑：
> 1. `except` 后面**必须跟冒号 `:`**，下面的救援代码要**缩进**。
> 2. 别写**裸 `except:`**（不带异常类型）——它会把所有错误都吞掉，真正的 bug 也被悄悄藏起来，排错时一脸懵。**尽量写具体的异常类型**，比如 `except ZeroDivisionError`。

## 📋 常见异常类型：认雷大会

工坊里埋着好几种雷，学会**认脸**才能对症下药。下面是 6 种最常见的：

| 异常类型 | 什么时候踩到 | 触发例子 |
| --- | --- | --- |
| `ZeroDivisionError` | 除数为 0 | `10 / 0` |
| `ValueError` | 值本身不对（转类型失败） | `int("abc")` |
| `TypeError` | 类型不匹配 | `"1" + 1` |
| `NameError` | 用了没定义的变量 | `print(age)`（age 没定义） |
| `IndexError` | 下标越界 | `[1, 2, 3][9]` |
| `KeyError` | 字典键不存在 | `{"a": 1}["b"]` |

把下面的代码当"引雷器"玩一玩：**每行都是不同的雷，取消注释引爆它**，看看报错长什么样：

```python
# 取消注释引爆每一颗雷，观察报错类型
# print(10 / 0)          # ZeroDivisionError：除数为 0
# print(int("abc"))      # ValueError：int() 转不了 "abc"
# print("1" + 1)         # TypeError：字符串和数字不能相加
# print(age)             # NameError：age 没有定义
# print([1, 2, 3][9])    # IndexError：下标越界
# print({"a": 1}["b"])   # KeyError：键 "b" 不存在
print("工坊里埋了 6 颗雷，取消注释依次引爆它们吧！")
```

> ⚠️ 新手最容易踩的坑：
> 1. **程序会在第一颗被踩的雷处停下**——一次只看一颗雷的报错，别一次引爆一堆。
> 2. 报错信息要**读全**：`异常类型 + 冒号 + 具体原因`。比如 `ValueError: invalid literal for int() with base 10: 'abc'`——类型是 `ValueError`，原因是 "abc" 转不成整数。

## 🎀 else 与 finally：收尾也讲究

防弹衣还能更讲究。`try / except` 之外还有两个**可选配件**：

- `else:`——**没踩雷时才执行**：try 块一路顺风，就跑这里的"庆祝"代码
- `finally:`——**不管踩没踩雷都执行**：收尾动作（关灯、存盘、说再见）放这里

```python
try:
    num = int(input("请输入一个数字："))
    result = 100 / num
except ValueError:
    print("你输入的不是数字！")
except ZeroDivisionError:
    print("除数不能是 0！")
else:
    print("计算结果：", result)   # 没出错才执行
finally:
    print("本次计算结束")          # 一定执行
```

**防御式编程的好习惯**：能提前检查就提前检查（比如用 `if num == 0` 拦一下），拦不住的就用 `try / except` 兜底。**程序不崩溃，用户不骂娘**。

> ⚠️ 新手最容易踩的坑：
> 1. 块的位置顺序是固定的：`try` → `except`（可多个）→ `else` → `finally`。把 `else` 写在 `finally` 后面会直接**语法错误**。
> 2. `finally` 里的代码**一定会执行**——别把"正常情况才该做的事"放进去，否则踩雷时它也会跑。
