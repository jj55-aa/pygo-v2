# 独立挑战——网络驿站的结业大考

## 🚪 接口全景：前台的一来一回

网络驿站的前台只有一个小窗口。旅人走到窗口前，把纸条递进去（**请求**）；窗口里的小二看一眼纸条（**读请求**）、检查写没写清楚（**校验参数**）、转身去仓库办业务（**业务处理**）、再把结果递出窗口（**返回结果**）。一个「接口」，就是这完整的一来一回。

**接口 = 读请求 → 校验参数 → 业务处理 → 返回结果**。四个环节缺一不可、顺序也不能乱：纸条都没看就办业务，办的一定不是客人要的事；参数没校验就动手，垃圾参数会把业务直接弄崩。

```python
# 模拟一次完整的「请求 → 处理 → 响应」（纸条内容写死在代码里当测试数据）
op = "add"            # 请求：操作类型
args = "3 5"          # 请求：参数

if op == "echo":             # 业务处理：原样转交
    print(args)
elif op == "add":            # 业务处理：计算求和
    a, b = args.split()
    print(int(a) + int(b))
else:                        # 兜底：未知操作
    print("400 参数错误")
```

> ⚠️ 易错点：四步别混着写。**先读请求再干活**——参数都没拿到就处理，等于对着空气办业务；**校验放在业务前面**——等垃圾参数把业务弄崩了才想起来拦，已经晚了；每个环节只做自己的事，读请求的代码别顺手把结果也打印了。

## 🔍 参数校验：面单检查

驿站收件第一件事是看面单：收件人、地址**写没写**？写的是不是**人话**？面单都看不清就入库，包裹一定会寄丢。程序处理参数也是一样——**动手处理前，先确认参数「齐全」且「合法」**：

- **缺参数**：add 该有两个数字，只来了一个 → 拆完只剩一个数，取第 2 个就崩（IndexError）
- **非法值**：add 的参数里混进字母「abc」→ `int()` 转不动（ValueError）

```python
args = "3 abc"                  # 驿站收到的参数
parts = args.split()            # ['3', 'abc']
try:
    a = int(parts[0])           # 3
    b = int(parts[1])           # int("abc") 抛 ValueError！
except (ValueError, IndexError):
    print("400 参数错误")        # 校验失败：友好提示，程序不崩
else:
    print(a + b)                # 校验通过才进业务
```

> ⚠️ 易错点：校验必须写在业务处理**之前**；`int()` 转换一定要放在 **try 里面**才接得住；缺参数是 `IndexError`（parts[1] 不存在）、参数是字母是 `ValueError`——两种异常都要接住，漏一个就崩一个。

## ⚙️ 业务处理：驿站的三样本事

驿站的看家业务就三样：**转交（echo）**——把纸条原样递出去；**算账（add）**——把两个数字加出总价；**报时（time）**——翻出站里的时钟报一声。业务处理，就是把「校验过的参数」加工成「要返回的结果」。

**同一份接口代码里，不同操作走不同的分支（if/elif/else 分发），每个分支完成一件具体业务**；业务只认校验过的参数，不再操心参数对不对。

```python
op = "add"          # 请求：操作类型（echo / add / time）
args = "3 5"        # 请求：参数

if op == "echo":                    # 业务一：原样转交
    print(args)
elif op == "add":                   # 业务二：计算求和
    a, b = args.split()
    print(int(a) + int(b))
elif op == "time":                  # 业务三：返回固定信息
    print("驿站时间：2026-08-20")
```

> ⚠️ 易错点：`input()` / `split()` 拿到的**全是字符串**——"3" + "5" 是 "35" 不是 8，算数前必须 `int()` / `float()` 转换；分支用 `elif` 串起来，漏写 `else` 时未知操作就没人处理；每类操作只办自己的事，别把 echo 的文本拿去当数字算加法。

## 🛡️ 异常兜底与返回：400 与 404

驿站柜台备着三句标准话术：**400**「你填的面单有问题」（参数错误）、**404**「驿站里没有你要找的东西」（资源不存在）、**200**「办妥了」（成功）。真实网页服务靠这些 **HTTP 状态码**告诉浏览器结果；我们在控制台模拟接口，就把状态码对应的提示直接打印出来。

**400 = 请求本身有问题**（缺参数 / 参数非法 / 未知操作）；**404 = 请求的资源不存在**（没有这个页面或接口）。正确姿势永远是：**try/except 接住异常 + 友好错误返回**——程序不崩，用户看得懂。

```python
op = "fly"                # 请求：一个不存在的操作
args = "随便写点什么"

if op == "add":
    parts = args.split()
    try:
        a, b = int(parts[0]), int(parts[1])
    except (ValueError, IndexError):
        print("400 参数错误")     # 参数非法 → 400
    else:
        print(a + b)             # 正常 → 返回结果
else:
    print("400 参数错误")         # 未知操作 → 400
```

> ⚠️ 易错点：**400 是参数问题、404 是资源不存在**，别混用；`except` 要写**具体异常类型**（ValueError / IndexError），别用裸 `except:` 把别的 bug 也悄悄吞掉；错误提示要**统一友好**——用户看的是「400 参数错误」，不是一屏红色 traceback。
