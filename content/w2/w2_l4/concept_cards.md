# 独立挑战——立项大厅的结业大考

## 🧭 立项三件套：开工前的「图纸三合一」

**类比**：立项大厅里盖一栋楼，动手搬砖之前得先有一张图纸。一张好图纸至少画清三部分：**需求**——这栋楼给谁住、解决什么生活难题；**技术栈**——用什么材料盖（砖头、水泥还是钢结构）；**计划**——先打地基还是先装窗户，盖坏了拿什么补救。三样齐了，图纸才合格；缺一样，楼大概率盖到一半就烂尾。

**定义**：**立项三件套** = 需求清晰 + 技术栈合适 + 计划有保险。需求回答「做什么、给谁、为什么」，技术栈回答「用什么做」，计划回答「先做什么、坏了怎么办」。三件套齐了，才轮到 AI 开工——就像 u7 档案课的「读 → 拆 → 算 → 写」四步套路，立项也有自己的三件套套路。

```python
# 立项三件套：用字典模拟一份「立项文档」
project = {
    "需求": "给奶茶店老板做点单小程序",
    "技术栈": "小程序前端 + Python 后端",
    "计划": "先做 MVP，每阶段 Git 提交",
}
for part in ["需求", "技术栈", "计划"]:
    if project[part]:
        print(part + "：已写清楚")   # 三部分都齐了，可以开工
```

> ⚠️ 易错点：
> 1. **立项 ≠ 写代码**：三件套没聊清就让 AI 开工，等于没图纸就搬砖——方向错了，整个地基都要重来。
> 2. **三件套缺一不可**：有人只写需求忘了技术栈，有人写了计划却忘了保险（备份/测试）——「齐全」比「每部分都完美」更重要。

## 🔍 需求清晰度评估：需求三问

**类比**：点外卖只说一句「来点吃的」，老板没法做；说清「给小孩吃、不要辣、20 分钟内送到」，单子才下得准。和 AI 聊需求也一样，问清三件事，AI 才不会靠猜。

**定义**：**需求三问** = ① 给谁用？② 解决什么问题？③ 怎么算成功？三问都答得上来，需求才算清晰。把答案写进立项文档：目标用户、核心问题、**验收标准**（第一版做到什么程度才算完成）。

```python
doc = "给奶茶店老板做点单小程序，解决排队难，上线一周能下 50 单算成功。"
questions = ["给谁用", "解决", "成功"]
for q in questions:
    print(q, "→", "有" if q in doc else "没有")
```

> ⚠️ 易错点：
> 1. **模糊需求最危险**：「做个网站」没说给谁用、解决什么，AI 只能脑补，写出来的往往不是你要的。
> 2. **别漏验收标准**：「怎么算成功」不是可有可无——没有它，AI 说「完成」，你就只能听它的。

## 🧰 技术栈合适度：三原则

**类比**：选材料讲究合适：豆腐房用砖就够，非要上钢结构，又贵又难维护。给 AI 选技术栈也一样——不是比谁听着高级，而是比谁合适。

**定义**：**技术栈** = 这个项目用什么技术来做，通常是**前端 + 后端 + 数据库**的组合。选它守**三原则**：① **匹配产品形态**（网页、小程序、App 各配各的）；② **够用就好**（普通官网别上重型架构，别为炫技选冷门）；③ **生态成熟**（用的人多、还在维护、AI 也熟）。定了就别来回摇摆——每换一次，前面的地基重打一次。

```python
doc = "前端：小程序页面，后端：点单接口，数据库：订单表"
tech = ["前端", "后端", "数据库"]
for t in tech:
    print(t, "→", "有" if t in doc else "没有")
```

> ⚠️ 易错点：
> 1. **别为炫技选冷门**：新框架听着酷，但没人维护、AI 不熟，出问题没人救。
> 2. **定了就别摇摆**：今天 React 明天 Vue，后端今天 Python 明天 Go——每摇摆一次，前面的地基就白打一次。

## 🗓️ 计划完备度：流程 + 保险

**类比**：装修房子：先水电、再贴砖，而且每装完一步拍个照存档——万一返工，照着照片就能还原。做项目也一样：一条**流程线** + 一份**保险**。

**定义**：**开发流程** = 立项 → 文档 → 骨架 → 开发 → 测试 → 部署 → 上线；**项目保险** = Git 存档（每完成一个能正常运行的阶段就提交一次）+ 备份 + 里程碑 + 小步快跑。计划完备 = **流程清楚**（先做什么后做什么）+ **有后悔药**（AI 改坏了能回退到稳定版本）。

```python
doc = "先写立项文档，每阶段 Git 提交一次，写完就测试。"
plan = ["文档", "备份", "测试"]
for p in plan:
    print(p, "→", "有" if p in doc else "没有")
```

> ⚠️ 易错点：
> 1. **光有流程没保险**：AI 改坏代码却没有存档，只能让它越补越乱，最后整个项目烂尾。
> 2. **计划别抠死到天**：阶段先定大方向，别急着细化每一步——需求会变，小步快跑、做完一段验收一段才是正解。
