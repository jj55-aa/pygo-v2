# 技术栈选择——选对工具再开工

## 🧰 技术栈就是工具箱：先选工具，再开工

你站在「立项大厅」的工具墙前。墙上挂满了扳手、螺丝刀、电钻、卷尺……每一件都有人用，但**没有一个工程会把它们全带上**——装修水管就带管钳，拧螺丝就带螺丝刀。选错工具，活儿干到一半就得返工。

写程序也一样。**技术栈（Technology Stack）就是这个项目要用的一整套技术**：前端用什么画页面、后端用什么处理逻辑、数据库用什么存数据，外加框架和辅助工具。它们不是一个软件，而是一个**组合**——就像一套工具箱，缺一件都会卡壳。

一个 Web 项目最朴素的「工具箱三件套」：

| 位置 | 选什么工具 | 干什么活 |
| --- | --- | --- |
| 前端 | HTML + CSS + JS | 画页面、按钮、表单 |
| 后端 | Flask（Python 框架） | 处理请求、判断逻辑 |
| 数据库 | SQLite | 长期保存数据 |

用字典把这套工具箱装起来看看：

```python
# 用字典模拟一个 Web 项目的"技术栈工具箱"
stack = {
    "前端": "HTML + CSS + JS",
    "后端": "Flask（Python 框架）",
    "数据库": "SQLite",
}
for part, tool in stack.items():
    print(part, "→", tool)
```

> ⚠️ 新手最容易踩的坑：
> 1. **技术栈不是「一个软件」**，是前端 + 后端 + 数据库的组合——只定一个可不够。
> 2. **产品形态没定就先选栈**，项目会越写越乱：今天用这套、明天换那套，代码变成一锅粥——这就是 AI 飘移（AI Drift）的根源。

## 🗂️ 四类项目，四套常见组合

工具墙上的工具虽然多，常见工程也就那么几类。先想清楚产品最终**以什么形式呈现**，再去工具墙取对应的那套：

| 项目类型 | 前端 | 后端 | 数据库 |
| --- | --- | --- | --- |
| Web 应用（网站） | HTML + CSS + JS | Flask（Python 框架） | SQLite |
| 小程序 | 小程序原生框架（如微信小程序） | 云开发 / Flask | 云数据库 / SQLite |
| 脚本（自动化小工具） | 不需要 | 不需要 | 不需要 |
| 桌面小工具 | Tkinter / Electron | 内嵌在程序里 | 本地 SQLite |

- **Web 应用**：用户用浏览器访问，前端、后端、数据库三件套齐活。
- **小程序**：跑在微信等平台里，要遵守平台的开发规范——**不能把网页原样搬过去**。
- **脚本**：就是一段跑完就结束的程序（批量改文件名、整理报表），**不需要界面、不需要服务器**，Python 标准库就够。
- **桌面工具**：双击打开、有窗口的软件，用 Tkinter 或 Electron 做界面，数据存在本地。

用字典把这四套组合装起来，随时查：

```python
# 四类项目的常见技术栈组合（模拟）
combos = {
    "web": "前端 HTML+CSS+JS，后端 Flask，数据库 SQLite",
    "miniapp": "小程序原生框架，后端云开发，数据库云数据库",
    "script": "Python 标准库，无需前端后端",
    "desktop": "Tkinter 桌面界面，本地 SQLite 存数据",
}
for ptype, advice in combos.items():
    print(ptype, "→", advice)
```

> ⚠️ 新手最容易踩的坑：
> 1. **小程序 ≠ 网页**：小程序要守平台规范，直接把网页代码搬过去跑不起来。
> 2. **脚本不需要前后端**：写个「批量改文件名」的脚本还配个 Flask + 数据库，纯属给自己加戏。

## ⚖️ 三原则：够用、生态、团队熟

工具墙上有贵的、有新的、有听上去很唬人的——选哪套？记住**三条原则**：

1. **够用就好**：项目复杂度匹配工具复杂度。普通官网犯不着上重型微服务架构，轻量小工具犯不着引一堆大框架。**别为炫技选冷门**。
2. **生态成熟**：用的人多、还在维护、文档全、社区有讨论。看一个开源框架靠不靠谱，可以查它的 GitHub Star 数、最近提交时间、许可证是否允许商用——**踩过的坑有人替你踩过，才是好工具**。
3. **团队（AI）熟悉**：你是和 AI 一起写代码的。选 AI 容易理解、你自己也看得懂的技术，并让它基于立项文档给出**唯一推荐方案**——而不是甩给你三四套备选，让你来回摇摆。

用代码模拟一下「三原则打分」：给每个候选技术按三条原则打分，选总分最高的：

```python
# 模拟：按"够用/生态/熟悉"三原则给候选技术打分
candidates = {
    "Flask":   {"够用": 9, "生态": 9, "熟悉": 8},
    "新潮框架A": {"够用": 2, "生态": 3, "熟悉": 2},
}
for name, scores in candidates.items():
    total = scores["够用"] + scores["生态"] + scores["熟悉"]
    print(name, "总分：", total)
```

> ⚠️ 新手最容易踩的坑：
> 1. **为炫技选冷门**：框架没人用、没人维护，踩坑只能自己扛，AI 也帮不上忙。
> 2. **技术路线不稳**：今天听人说这个好就换，明天看那个新又换——项目最后变成一堆拼起来的代码。选型要**收敛到一条主线**。

## 🏗️ 判题环境：没有 Flask、没有网络

这一课是**认知模拟**：你的代码跑在浏览器里的 Pyodide 环境——**没有真的 Flask、没有网络请求、也没有真数据库**。所以我们不真装框架，而是用标准库（字符串、字典、input）**模拟「选型建议」**。

模拟的思路很简单：**读入项目类型 → 关键词判断 → 输出对应的建议文本**。这正是后面几道 code 题的解法原型：

```python
# 模拟选型建议：按项目类型输出技术栈（标准库即可，不用装任何框架）
def advice(ptype):
    if ptype == "web":
        return "前端 HTML+CSS+JS，后端 Flask，数据库 SQLite"
    if ptype == "miniapp":
        return "小程序原生框架，后端云开发，数据库云数据库"
    if ptype == "script":
        return "Python 标准库，无需前端后端"
    if ptype == "desktop":
        return "Tkinter 桌面界面，本地 SQLite 存数据"
    return "未知类型：请先确认产品形态"

print(advice(input()))
```

> ⚠️ 新手最容易踩的坑：
> 1. **别 `import flask` / `import requests`**：判题环境里没有这些库，import 直接报错——用字典和 if 判断来模拟就好。
> 2. 模拟输出的「建议文本」只是练习选型思路，**和真实部署无关**；但判断逻辑（先定形态、再配工具）在任何环境都适用。
