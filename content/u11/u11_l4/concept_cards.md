# 并发抓取——多窗口同时上，也要记得克制

## 🎰 串行 vs 并发：一个人排队 vs 多窗口同时上

蜘蛛峡谷的情报中心只有**一个办事窗口**：你想抓 6 面情报墙，只能排着队——发一个请求、等响应回来、再发下一个。这叫**串行（Serial）**：一件事做完，才做下一件事。6 面墙、每面等 0.5 秒，就得干等 3 秒。

后来情报中心开了 **3 个窗口**：3 个请求同时发出去，等待的时间重叠了——这叫**并发（Concurrent）**：多件事同时推进，宏观上「一起上」。6 面墙还是每面等 0.5 秒，但 3 面一起等，总共只要 1 秒。

一句话记忆：**串行 = 一个人排队，并发 = 多窗口同时上**。

```python
# 串行：一个一个来
for wall in [1, 2, 3]:
    print(f"抓取情报墙 {wall} …… 完成")

# 并发（概念）：多件事一起推进
# 判题环境里我们用「分批循环」模拟，不真开线程（见第 4 张卡）
```

> ⚠️ 新手最容易踩的坑：
> 1. **并发 ≠ 一定更快**：如果是大量纯计算（CPU 密集任务），多线程反而可能不加速——为什么？下一张卡的 GIL 会告诉你。
> 2. **并发不是「所有事同一瞬间完成」**：它是「一起推进」，该等的时间还是会等，只是大家不等彼此。

## 🧵 多线程与 GIL：概念扫盲

面馆只有一个灶台时，一个厨师只能一锅一锅炒。请来 3 个厨师（**线程**），就能 3 口锅同时开火——**线程（Thread）就是程序里一条独立的执行流程**。一个程序默认只有主线程，用 `threading` 模块可以开更多：

```python
import threading

def grab(name):
    print(f"{name} 开始抓取情报")

t = threading.Thread(target=grab, args=("线程A",))
t.start()   # 启动线程（不 start 它永远不干活）
t.join()    # 主线程等它干完再继续
```

但 Python 有个著名的家伙叫 **GIL（Global Interpreter Lock，全局解释器锁）**：**同一时刻，一个 Python 进程里只有一个线程在执行 Python 代码**。就像面馆虽然请了 3 个厨师，灶台却只有一个，大家轮流用：

- **CPU 密集任务**（大量计算）：抢同一个灶台，轮流切菜不如一个人专心切 → 多线程**不加速**
- **I/O 密集任务**（等网络、等文件）：「等」的时候灶台空着，别人可以上来用 → 多线程**明显提速**
- 爬虫就是典型的 I/O 密集任务，所以**多线程爬虫能提速**

> ⚠️ 新手最容易踩的坑：
> 1. **线程执行顺序不确定**：谁先抢到 CPU 谁先跑，写多线程代码千万别依赖输出顺序。
> 2. **多个线程改同一个变量会「数据竞争」**：「读取 → 修改 → 写回」三步之间可能被别的线程打断，结果错乱，需要加锁（Lock）保护。概念知道即可——本课练习不真开线程，用循环模拟。

## ⚡ 并发爬虫：为什么爽，也为什么危险

把并发用到爬虫上，效果立竿见影：爬 100 个页面，串行是「发请求 → 等 0.5 秒 → 再发下一个」，要 50 秒；**3 个线程同时发**，等待重叠，可能只要 17 秒。爽！

但并发是**双刃剑**：你把线程数开到 50 猛抓——服务器压力暴增，网站可能变卡甚至崩掉；网站管理员一眼就认出你，**封 IP、上验证码、403 拒绝**，一夜回到解放前。所以真正的爬虫要**克制**：

- **控制并发数**：`max_workers` 别开太大，学习用 3~5 个足够
- **请求间隔**：每个请求之间随机休息（`time.sleep`），别像机关枪
- **看 robots.txt**：遵守网站规则，别越界
- **失败重试**：请求失败等几秒再试一次，别死磕

```python
from concurrent.futures import ThreadPoolExecutor
import time

def fetch(url):
    time.sleep(0.2)          # 模拟等网络
    return f"{url} 抓取完成"

with ThreadPoolExecutor(max_workers=3) as pool:   # 最多 3 个同时抓
    for r in pool.map(fetch, ["情报墙1", "情报墙2", "情报墙3", "情报墙4", "情报墙5", "情报墙6"]):
        print(r)
```

> ⚠️ 新手最容易踩的坑：
> 1. **并发不是越多越好**：线程创建有开销、网络带宽有限，开 50 个不一定比 5 个快，还更容易被封。
> 2. **只讲速度不讲礼貌** = 给服务器添乱：爬虫的第一准则不是快，是**不添乱**。

## 📦 分批处理：判题环境用循环模拟

6 面情报墙一次全上，容易乱，也容易把情报网冲垮。聪明的做法是**分批处理（batch processing）**：把大量任务切成若干小组，一组一组来——每批内部「同时抓」（概念上相当于一小撮并发），批与批之间排队。6 面墙、每批 3 面 → 2 批，每批内部 3 个请求一起发。

判题环境（Pyodide）里**不真开线程**，我们用**普通循环 + 切片**模拟分批：

```python
walls = [1, 2, 3, 4, 5, 6]
k = 1
for i in range(0, len(walls), 3):
    batch = walls[i:i + 3]          # 切出当前这一批
    print(f"批次{k}：" + " ".join(map(str, batch)))
    k += 1
# 输出：
# 批次1：1 2 3
# 批次2：4 5 6
```

关键就两行：`range(0, len(walls), 3)` 让下标每次前进 3（一批的大小）；`walls[i:i + 3]` 用切片取出这一批。

> ⚠️ 新手最容易踩的坑：
> 1. **最后一组可能不足 3 个**：比如 4 面墙，第 2 批只有 1 面——切片不会越界报错，属正常。
> 2. **`range(0, n, m)` 的步长要写对**：步长 = 每批大小，写错批就分歪了。
> 3. **别在判题环境真开线程**：概念归概念、练习归练习，这里统一用循环模拟分批。
