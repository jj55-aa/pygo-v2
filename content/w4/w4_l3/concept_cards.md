# 环境搭建——让代码跑起来的前提

## 🚀 环境就是「燃料加注」：代码跑起来的前提

你把项目代码推上了发射台，满怀期待按下点火按钮——火箭纹丝不动。不是火箭坏了，是**燃料箱空空如也**：代码是火箭，但让它飞起来的那套东西还没准备好。

服务器也一样。刚买的服务器连上去，往往是个黑乎乎的**命令行窗口**：操作系统装好了，里面却空空如也——就像刚交房的**毛坯房**，四面墙（操作系统）有了，水电气（运行环境、数据库、Web 服务器）都没通，没法直接住进去。你的代码放上去，照样跑不起来。

**环境（Environment）** 就是代码运行所依赖的**一整套底层软件和配置的合称**。代码传上服务器 ≠ 能跑；**环境搭好，代码才跑得起来**——这正是发射台点火前的「燃料加注」。

```python
# 模拟：检查「燃料」加没加（环境装没装好）
checks = {"Python 运行环境": True, "Node 运行环境": False, "数据库": True}
for name, ok in checks.items():
    print(name, "→", "已就绪" if ok else "未装好！")
```

> ⚠️ 新手最容易踩的坑：
> 1. **代码放上去 ≠ 能跑**：空服务器除了操作系统什么都没有，环境没搭好，项目必然跑不起来。
> 2. 环境是**代码外面**的那一套运行条件，不是代码里写的配置——缺一样，代码就跑不了。

## 🧰 装什么：服务器环境「四件套」

给火箭加燃料，加的是「配方燃料」——不是随便什么油都行。服务器环境也一样，业内早有固定搭配，核心是**四件套**：

| 四件套 | 干什么 | 常见选择 |
| --- | --- | --- |
| **操作系统** | 整套环境的地基，所有软件都装在它上面 | Linux |
| **Web 服务器** | 站在最前面接住外部访问，再转给后端程序（大楼的「前台 + 门卫」） | Nginx / Apache |
| **数据库** | 专门存数据：用户、订单、内容都放这儿 | MySQL / PostgreSQL |
| **后端运行环境** | 执行后端语言写的代码 | Python / Node.js / Java(JDK) |

**上线 = 把本地开发用的那一整套，在服务器上重新装一份更正规、更扛并发的版本**。本地你已经装过 Python、装过数据库——那就是环境的「简化版」，服务器上要再来一份正式的。

不同语言配不同运行环境，就像**不同的电器要配不同的插座**：后端用 Python 就装 Python，用 Node 就装 Node.js——对不上，电器就不工作。

```python
# 模拟：服务器环境「四件套」检查清单
env_items = ["操作系统(Linux)", "Web服务器(Nginx)", "数据库(MySQL)", "Python运行环境"]
for item in env_items:
    print("□", item)
print("四件套凑齐，项目才有地方跑、有地方存、有人接住访问。")
```

> ⚠️ 新手最容易踩的坑：
> 1. 别只装运行环境，忘了数据库和 Web 服务器——「程序起得来」和「能被访问、能存数据」是三回事。
> 2. **SQLite 大坑**：本地开发用 SQLite（单文件轻量库）图方便，但带用户系统的产品上线前换成 MySQL/PostgreSQL，是**底层技术替换**不是改配置，极其折腾——开发初期就该让 AI 直接用生产级数据库。

## 🚪 端口与环境变量：程序的「门牌号」和「便签」

一台服务器上可以同时跑很多程序，外界怎么找到你要访问的那一个？靠**端口（Port）**——每个程序对外服务时占一个「门牌号」。访问 `http://服务器IP:8000`，就是敲 8000 门牌号找那个程序。常见约定：网站 80/443、数据库 3306。

程序需要的配置（数据库地址、密钥、端口号）**不写死在代码里**，而是放在**环境变量（Environment Variable）**里——像贴在程序门口的「便签」：换环境（本地 → 服务器）只改便签，不改代码，密钥也不会跟着代码传进仓库。

```python
import os

# 模拟：从环境变量读配置——PORT 没设置就用默认值 8000
port = os.environ.get("PORT", "8000")
print("程序在端口", port, "上提供服务")
```

> ⚠️ 新手最容易踩的坑：
> 1. 端口是程序的「门牌号」，不是网址也不是数据库名；访问一个程序 = IP/域名 + 端口。
> 2. 数据库地址、密钥这类配置**别写死在代码里**——放进环境变量，换环境只改配置不改代码，密钥也不会泄露到代码仓库。

## 🕳️ 常见坑：版本不对 / 端口占用 / 依赖缺失

燃料配方不对，火箭照样点不着。环境搭好之后，最常见的就是这三类坑：

1. **版本不对**：本地 Python 3.12 能跑的新语法，服务器只装了 3.8，直接报错——先 `python --version` 核对版本，再对齐。
2. **端口占用**：你想用 8000，但别的程序已经占着，新程序起不来（Address already in use）——换一个端口，或先停掉占用的程序。
3. **依赖缺失**：代码里 `import requests`，服务器上没装，报 ModuleNotFoundError——用 requirements.txt 把依赖记下来，一次性装齐。

**口诀：环境搭好才能跑代码；跑不起来，先查环境，再怀疑代码。** 查环境要「清单式」一项一项核：版本、端口、依赖全部通过，才算环境就绪。

```python
# 模拟：环境体检——一次查清版本、端口、依赖
checks = {"版本匹配": "是", "端口空闲": "否", "依赖齐全": "是"}
missing = [k for k, v in checks.items() if v != "是"]
print("还缺：" + "、".join(missing) if missing else "环境就绪")
```

> ⚠️ 新手最容易踩的坑：
> 1. 报错先看环境：ModuleNotFoundError → 依赖没装；Address already in use → 端口被占；版本语法报错 → 环境版本不对。别一上来就怀疑代码逻辑。
> 2. 环境检查是「清单式」的：一项一项核，全部通过才算就绪——这正是接下来 code 题要写的「环境检查清单」。
