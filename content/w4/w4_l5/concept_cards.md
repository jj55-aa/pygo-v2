# 独立挑战——发射台的结业大考

## 🚀 部署方案四要素：发射台的「四件套」

**类比**：发射台要把火箭送上天，发射前得备齐四件套：**火箭本体**（谁在飞）、**航线塔台**（往哪飞、别人怎么找到它）、**燃料补给**（拿什么飞）、**点火按钮**（什么时候飞、怎么飞）。部署一个项目就是一次「发射」——你手里的部署方案，也必须把这四件套交代清楚：

| 四件套 | 发射台里的角色 | 部署里的意思 |
| --- | --- | --- |
| 服务器 | 火箭本体 | 跑代码的那台机器（云服务器/主机） |
| 域名 | 航线塔台 | 别人访问你的网址（域名/DNS 解析） |
| 环境 | 燃料补给 | 运行需要的依赖、版本、端口 |
| 启动 | 点火按钮 | 怎么把程序跑起来、开机自启 |

**定义**：**部署方案四要素** = 服务器（代码跑在哪）+ 域名（别人怎么访问）+ 环境（依赖/端口配好没）+ 启动（怎么跑起来）。四件套齐全，方案才算「想清楚了」；缺一件，就像火箭少个零件——要么飞不起来，要么飞到一半掉下来。

```python
# 用字典模拟「部署方案四要素」清单
plan = {
    "服务器": "一台 2 核 4G 云服务器",
    "域名": "www.example.com",
    "环境": "Python 3.11 + 依赖库 + 端口 8000",
    "启动": "运行 app.py，开机自启",
}
for key, value in plan.items():
    print(key, "→", value)
```

> ⚠️ 易错点：
> 1. **「提到」≠「想清楚」**：只写一个「服务器」不写哪台、什么配置；只写「部署」不写怎么启动——空泛的关键词不算数，四要素要**具体**才有意义。
> 2. **四要素别漏项**：很多人写到「服务器 + 启动」就以为齐了——域名（用户怎么访问）和环境（依赖装没装）最容易忘，偏偏少了它俩项目根本用不了。

## 🔍 方案评估：按关键词给四要素打分

**类比**：拿到一份部署方案，怎么判断它清不清楚？像体检一样**按关键词扫描**：四件套每件都有几个「信号词」，方案里出现哪个词，就说明它提到了哪个方向——服务器方向看有没有 服务器/主机/云；域名方向看 域名/DNS；环境方向看 环境/依赖/端口；启动方向看 启动/运行/部署。

**定义**：**方案评估** = 用四组关键词扫描方案文本，数一数**每个方向命中几个关键词**（同一个词出现多次只算一次）。计分规则：每个方向最多算 **2 分**（命中 2~3 个关键词都算满），四个方向满分 **8 分**——分越高，方案越「想清楚了」。

```python
text = "租一台云服务器，绑定域名，装好依赖，启动项目"
keys = {
    "服务器": ["服务器", "主机", "云"],
    "域名": ["域名", "dns"],
    "环境": ["环境", "依赖", "端口"],
    "启动": ["启动", "运行", "部署"],
}
t = text.lower()                       # 统一小写，DNS/dns 都能匹配
total = 0
for name, words in keys.items():
    hit = sum(1 for w in words if w in t)   # 命中几个关键词（去重）
    total += min(hit, 2)                     # 每个方向最多 2 分
    print(name, "命中", hit, "个关键词")
print("清晰度：", total, "分（满分 8）")
```

> ⚠️ 易错点：
> 1. **大小写要对齐**：DNS 在方案里可能写成小写 dns——先把文本 `text.lower()` 统一转小写再匹配，否则明明提到了却数不到。
> 2. **命中要「去重」**：一个关键词在方案里出现三次（比如「部署到服务器，服务器配置…」）也只算命中一次；计分封顶每方向 2 分，不是关键词出现越多分越高。

## 🔧 缺失分析：哪个方向最该补强

**类比**：体检报告出来，哪项指标最低就先补哪项——缺铁补铁、缺钙补钙。部署方案也一样：四个方向里**命中关键词最少**的那个，就是最该补强的方向。比如方案一个字没提域名，用户访问不到网站，补强方向就是「域名」。

**定义**：**缺失分析** = 找出四个方向中**命中数最少**的一个，它就是「建议补强」的方向；如果并列，按 服务器 → 域名 → 环境 → 启动 的顺序取靠前的那个（程序结果才稳定）。

```python
scores = {"服务器": 2, "域名": 1, "环境": 2, "启动": 1}   # 各方向命中数
best = "服务器"
for name in ["域名", "环境", "启动"]:        # 固定顺序，并列取靠前
    if scores[name] < scores[best]:
        best = name
print("建议补强：", best)                    # 域名（命中最少）
```

> ⚠️ 易错点：
> 1. **看「命中数」不是看「分数」**：分数已经封顶 2 分，看不出是命中 2 个还是 3 个关键词；缺失分析要用**原始命中数**比，少的才是缺的。
> 2. **并列要有固定顺序**：两个方向同样少时，不规定顺序程序每次跑的结果都不一样——按 服务器 → 域名 → 环境 → 启动 固定取第一个。

## ✅ 综合验收：四步走完，方案清不清楚一目了然

**类比**：发射前最后一道总检：四件套齐不齐、每件有没有具体交代、缺的有没有补强计划——全部通过才敢按点火按钮。检查一份部署方案，也是同一条流水线：**读进来 → 扫描计分 → 找缺失 → 兜底空方案**。

**定义**：**综合验收** = ① 读入方案文本；② 四方向关键词扫描，每方向最多 2 分，算出清晰度（满分 8）；③ 找命中数最少的方向，给出「建议补强」；④ 方案是空的（或只有空白）时，打印「没有内容」兜底，而不是算出一个「0 分」糊弄人。四步走完，一份部署方案清不清楚，一眼看穿。

```python
import io

# 模拟读入一份部署方案文本（quest 里用 sys.stdin 从测试输入读）
text = io.StringIO("租一台云服务器，绑定域名，装好依赖，启动项目").read()
if not text.strip():
    print("没有内容")
else:
    t = text.lower()
    keys = [("服务器", ["服务器", "主机", "云"]),
            ("域名", ["域名", "dns"]),
            ("环境", ["环境", "依赖", "端口"]),
            ("启动", ["启动", "运行", "部署"])]
    scores, total = {}, 0
    for name, words in keys:
        hit = sum(1 for w in words if w in t)
        scores[name] = hit
        total += min(hit, 2)
    print("部署方案清晰度：%d 分" % total)      # 满分 8
    best = "服务器"
    for name, _ in keys[1:]:
        if scores[name] < scores[best]:
            best = name
    print("建议补强：%s" % best)
```

> ⚠️ 易错点：
> 1. **空输入要最先兜底**：`if not text.strip(): print("没有内容")` 要放在算分**之前**，并且算分逻辑放进 else 里——否则空方案会打出「清晰度：0 分」，那不是人话。
> 2. **四步顺序别乱**：先读、再算分、然后找缺失、最后才谈建议——缺失分析要建立在扫完所有方向之后，边扫边找会把漏掉的方向错过。
