# 网站是由什么组成的

## 🏪 网站三件套：门面、账房、仓库

你来到了「网络新大陆」的海岸。眼前立着一座热闹的驿站：门前挂着招牌、摆着菜单，客人进进出出；里屋的账房先生噼里啪啦打算盘；后院仓库里堆满了货物。

一个网站，就像这座驿站，也由**三件套**搭成：

| 三件套 | 驿站里的角色 | 负责什么 |
| --- | --- | --- |
| 前端 | 门面（招牌、菜单、桌椅） | 用户看到的页面、按钮、表单 |
| 后端 | 账房（算账、记账的先生） | 处理请求、判断逻辑（比如密码对不对） |
| 数据库 | 仓库（存放货物的库房） | 长期保存数据（账号、订单、文章） |

**前端 = 门面**：你在浏览器里看到的一切——颜色、布局、按钮——都是它"画"出来的。
**后端 = 账房**：你看不见它，但登录时判断密码对不对、下单时算总价，都是它在背后干活。
**数据库 = 仓库**：数据不能一直攥在代码手里（程序一重启就没了），要放进仓库长期保存。

用 Python 的字典，就能把「网站三件套」装起来看看：

```python
# 用字典模拟"网站三件套"
site = {
    "前端": "门面：用户看到的页面",
    "后端": "账房：处理请求的逻辑",
    "数据库": "仓库：保存数据的仓库",
}
for part, job in site.items():
    print(part, "=", job)
```

> ⚠️ 新手最容易踩的坑：
> 1. **前端 ≠ 后端**：页面好看是前端的事，密码对不对是后端的事——别把锅全甩给页面。
> 2. **数据库存的是「数据」，不是「页面」**：网页是前端根据数据"画"出来的，不是从数据库里原样搬出来的。
> 3. 这课是**认知模拟**：判题环境没有真网络、真数据库，我们用字典和字符串来模拟三件套。

## 🌐 浏览器与服务器：谁请求谁响应

驿站有了，谁来光顾？——**浏览器**是顾客，**服务器**是店家。

- **浏览器（客户端）**：你点开网址的那一瞬间，它代表你向店家"点菜"——发出一条**请求（request）**
- **服务器（server）**：守在驿站里的店家，收到请求后把菜做好端上来——返回一条**响应（response）**

**打开一个网页 = 发一次请求 + 拿一次响应**。没有请求，服务器不会主动把页面塞给你；没有响应，浏览器就只能干等。

用两个字典模拟一次「请求 → 响应」：

```python
# 用两个字典模拟一次"请求 → 响应"
request = {"谁": "浏览器", "动作": "发请求", "要": "首页内容"}
response = {"谁": "服务器", "动作": "回响应", "给": "页面内容"}

print("请求：", request)
print("响应：", response)
```

> ⚠️ 新手最容易踩的坑：
> 1. **请求是浏览器发起的**，服务器是被动等待、有求才应——不是服务器把整个网站"推"给你。
> 2. 服务器返回的是**处理结果（页面内容）**，不是把硬盘里的代码整个搬给你。

## 🚚 一次访问的全过程：从输入网址到看到页面

你输入网址、按下回车，到页面出现在屏幕上——中间发生了什么？一共 **5 步**：

1. **输入网址**：比如 `https://www.example.com/index.html`
2. **DNS 翻译**：把「域名」（www.example.com）翻译成计算机认识的 **IP 地址**——就像把"老王家的店"翻译成门牌号
3. **发送请求**：浏览器带着这个 IP，向服务器发出请求（request）
4. **收到响应**：服务器处理完，返回响应（response）——里面装着页面内容
5. **渲染页面**：浏览器把内容"画"成你看到的页面

跑一跑下面这段模拟代码，顺便用字符串方法把网址拆开、找到域名：

```python
# 模拟一次访问的 5 个步骤
steps = ["输入网址", "DNS 翻译域名", "浏览器发请求", "服务器回响应", "浏览器渲染页面"]
for i, step in enumerate(steps, 1):
    print(i, "→", step)

# 用字符串模拟拆开网址：找到域名
url = "https://www.example.com/index.html"
parts = url.split("/")
print("域名：", parts[2])
```

> ⚠️ 新手最容易踩的坑：
> 1. **DNS 是「翻译」**（域名 → IP），不是"上网"本身；网址里那个 `https://` 是协议，域名在它后面。
> 2. 5 步有**先后顺序**：没发请求就不会有响应，没拿到响应就渲染不出页面。

## 🧭 为什么先看懂结构，再学开发？

在「网络新大陆」上，你多半不是一个人手写代码，而是和 AI 一起干活（Vibe Coding）。这时候，**看懂结构比会写代码更重要**——因为你得知道自己在让 AI 写什么、改什么、验收什么。

- **分清问题层级**：页面难看不代表整个网站烂——可能是前端布局问题，也可能是后端接口没给对数据，还有可能是数据库结构不对。分不清层级，就会越改越乱。
- **页面能跑 ≠ 功能完成**：按钮能点、列表能看，可能是写死的假数据——数据真的存进数据库了吗？密码真的校验了吗？
- **敏感操作必须放后端**：前端代码最终会跑到用户的浏览器里，密钥、密码、支付逻辑写在页面里等于贴在大街上。账号密码存在**数据库**，判断对不对交给**后端**。

用字典模拟一个「登录」功能，看看三件套怎么各司其职：

```python
# 模拟：一个"登录"功能，三件套各自负责什么
login = {
    "前端": "展示登录框，收集账号密码",
    "后端": "判断密码对不对，生成登录状态",
    "数据库": "长期保存账号和密码",
}
for part, work in login.items():
    print(part, "负责", work)
```

> ⚠️ 新手最容易踩的坑：
> 1. 别把所有问题都丢给「页面优化」——先想清楚这是前端、后端还是数据库的问题。
> 2. 别把秘密放前端：密钥、密码、支付逻辑，一律放后端，数据进数据库。
