## 🌐 网址就是资源的"门牌号"：URL 与请求方法

想象你来到一座大城市，想找一家店喝奶茶：光喊"我要买奶茶"没用，你得先知道**地址**。浏览器也一样——你想从网上拿任何一个资源（网页、图片、数据），都得先给出它的地址。这个地址就是 **URL**（Uniform Resource Locator，统一资源定位符），也就是你平时叫的"网址"。

一个完整的 URL 由几部分组成：

- **协议**：`https://`——按什么规则通信（`http` 明文、`https` 加密更安全）
- **域名**：`www.baidu.com`——网站的"门牌号"，告诉你在哪座城市哪条街
- **路径**：`/s`——进了门找哪个房间
- **参数**：`?wd=python`——问号后面跟的"备注"，比如搜索关键词

有了地址，还要告诉服务器"你想干嘛"。HTTP 提供两种最常见的**请求方法**：

| 方法 | 干什么 | 生活类比 |
| --- | --- | --- |
| `GET` | 向服务器**要数据**（查询、读取） | 去柜台问"今天有什么？" |
| `POST` | 向服务器**提交数据**（登录、上传） | 填一张表单交上去 |

```python
# 一个 URL 拆开看：协议 + 域名 + 路径 + 参数
url = "https://www.baidu.com/s?wd=python"
# 协议 https  域名 www.baidu.com  路径 /s  参数 wd=python
print("URL 就是网络资源的地址，GET 要数据，POST 交数据")
```

> ⚠️ 新手最容易踩的坑：
> 1. **URL 不是乱码**，它有固定结构：协议、域名、路径、参数四件套，问号 `?` 后面才是参数。
> 2. 想**读取**数据用 `GET`，想**提交**数据用 `POST`，别搞反——GET 也能在 URL 问号后面带参数，但它本质是"要"，不是"交"。

## 🚦 状态码：服务器给你的"回执暗号"

你向服务器发了请求，服务器必须**回话**——但回的不是一句话，而是一个三位数，叫 **状态码（status code）**。它就像快递回执：不用拆开包裹，看单号就知道这单成没成。

| 状态码 | 含义 | 生活类比 |
| --- | --- | --- |
| `200` | 成功，数据正常返回 | 外卖到手，开吃 |
| `404` | 找不到这个资源（地址错了） | 跑错店了，根本没有这家店 |
| `500` | 服务器内部出错 | 店里后厨炸了 |

注意：**状态码不是 Python 报错**。404 的意思是：你的程序**成功**把请求送到了服务器，服务器回答"这个地址我这儿没有"。程序本身没崩，只是没拿到想要的东西。

```python
# 真实环境里，请求后先看状态码再决定怎么处理
# resp = requests.get("https://www.example.com/xxx")
# if resp.status_code == 200:
#     print("成功！可以处理数据了")
# elif resp.status_code == 404:
#     print("地址不对，检查一下 URL")
# elif resp.status_code == 500:
#     print("服务器出问题了，稍后再试")
print("200 成功 / 404 找不到 / 500 服务器出错")
```

> ⚠️ 新手最容易踩的坑：
> 1. **404 不是代码报错**，它是服务器给你的"回答"。看到 404 先检查 URL 拼没拼对，别去改代码逻辑。
> 2. 状态码是**三位数字**，判断用 `== 200`，别加引号写成 `== "200"`（那是字符串，不是数字）。

## 📦 requests：帮你跑腿的"外卖小哥"

发请求、收响应、解析数据，这些活你可以用标准库 `urllib` 自己干，但太啰嗦。爬虫圈人手一个的第三方库 **requests** 就是你的**外卖小哥**：你只要告诉它"去哪家店（URL）、点什么（方法）"，剩下跑腿的活它全包。

requests **不是标准库**，真实电脑上要先安装（还记得 u8_l3 的 pip 吗？）：`pip install requests`。不装就 `import requests`，会报 `ModuleNotFoundError`——在下面的代码框里点运行，你看到的就是这个坑。

**真实电脑上的用法**（本课练习环境没有网络，这段先读懂概念，跑不了）：

```python
# 真实电脑上使用（需要先 pip install requests）
import requests

resp = requests.get("https://www.example.com")   # 小哥出发：发一个 GET 请求
print(resp.status_code)   # 200：服务器回执
print(resp.text)          # 响应文本，常常是一长串 JSON 字符串
```

拿到响应对象 `resp` 后，最常用的三样宝贝：

- `resp.status_code`：状态码（200 / 404 / 500……）
- `resp.text`：响应**文本**（常常就是 JSON 字符串）
- `resp.json()`：把 JSON 文本**一步解析成 Python 数据**（下一张卡细讲）

> ⚠️ 新手最容易踩的坑：
> 1. **requests 要 pip 安装**：`pip install requests`。不装就 import，会报 `ModuleNotFoundError: No module named 'requests'`。
> 2. **本课练习环境（Pyodide）没有网络、没有 requests**，直接 `requests.get` 会报错。所以本课的代码题一律**不真联网**：用标准库 `json.loads` 解析模拟的 JSON 字符串——概念完全一样。
> 3. `resp.text` 拿到的是**字符串**，不是字典。想取字段，必须先解析（`.json()` 或 `json.loads`）。

## 🎯 API 与 JSON 响应：别人餐厅的"点餐窗口"

你想在程序里拿到天气、地图、翻译……总不能自己全世界建服务器吧？**API**（Application Programming Interface，应用程序编程接口）就是别人给你开的"**点餐窗口**"：你按它规定的地址和方法发请求，它把数据端出来给你，你的程序就能"借用"别人的能力。

API 返回的数据最常见的形式是 **JSON**——一种"字典样式"的文本，例如 `{"city": "北京", "temp": 25}`。注意 JSON 的键必须用**双引号**；它看起来和 Python 字典几乎一样，但本质是**字符串**。想取里面的字段，必须先解析成 Python 字典：

- 真实环境：`resp.json()`——响应对象的现成方法，一步搞定
- 本课练习环境：`json.loads(json字符串)`——标准库函数，效果一样

**两者本质是同一件事：把 JSON 文本变成 Python 数据（dict / list）**。会用 `json.loads`，你就懂了 `.json()` 在真实环境里干了什么：

```python
import json

# 模拟天气 API 返回的 JSON 字符串（练习环境没网络，用字符串模拟响应）
resp = '{"city": "北京", "temp": 25}'

# 真实环境里 resp.json() 干的正是这件事：JSON 文本 → Python 字典
data = json.loads(resp)
print(data["city"], data["temp"])   # 北京 25
```

> ⚠️ 新手最容易踩的坑：
> 1. **`.json()` 是响应对象的方法**（真实环境 `resp.json()`），**`json.loads()` 是标准库函数**（参数是字符串）。本课练习环境里 `resp` 是 JSON 字符串，所以用 `json.loads(resp)`。
> 2. JSON 的键必须用**双引号**（`"city"`）；写单引号，`json.loads` 会直接报错。
> 3. 解析完得到的是**字典**，用 `data["city"]` 取字段；`temp` 是数字 25，想拼成"25°C"要先用 `str()` 转成字符串。
